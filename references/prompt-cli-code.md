# 三层落地:哪些靠 prompt,哪些靠 CLI/MCP,哪些靠代码

> Phase 7/9 用(铁律「约束下沉 + 制品定性」)。核心:prompt 是最弱的约束层(可被遗忘/绕过),所以**越硬的约束越往下沉**;代码层负责「错不了」,CLI/MCP 层负责「做得到」,prompt 层负责「判断对」。
>
> **D1/D2 追加**:三层之外还有**企业控制面**(IAM/审批/CI-CD/日志审计/模型网关)。它不是可选的第四种实现,而是代码和 CLI 必须运行在其中的硬边界。

## 三层定义

| 层 | 管什么 | 特点 |
|---|---|---|
| **prompt(skill 指令)** | 判断与取舍:辨真伪、分约束、选交付形式、制品定性 | 灵活,可被绕过;只能指导,不能保证 |
| **CLI / MCP** | 执行与探测:lark-cli 取文档、git、文件操作、跑测试、调外部服务 | 动作可审计、可复现;没有判断能力 |
| **代码** | 不可变约束:鉴权检查、输入校验、权限白名单、密钥管理、重试/限流、审计日志 | 机械执行,不依赖记忆;写一次管一辈子 |

### 企业控制面(三层之外的硬边界)

| 控制面 | 管什么 | 对交付的要求 |
|---|---|---|
| IAM/SSO | 实名、角色、MFA、JIT | 不借账号;服务账号有 owner/到期 |
| 审批流 | 权限/数据/模型/变更 | 审批记录进证据台账 |
| CI/CD/制品库 | 构建、版本、签名、发布 | 不可变制品;变更号;回滚 |
| 日志/SIEM | 操作审计、告警 | 日志脱敏、不可篡改、保留期 |
| 模型网关 | 模型白名单、配额、脱敏 | 不绕过网关直连未批准端点 |

**这些控制面通常不归 FDE 改**;FDE 要做的不是「实现它」,而是「接进去、留证据、不绕过」。

## 判定三问(每个约束/动作都过一遍)

1. **能不能被代码机械检查?**(有没有明确的输入输出与规则)→ 能 → 落**代码**。
2. **是不是需要外部系统/服务完成的动作?**(取飞书文档、调 API、跑命令)→ 是 → 落 **CLI/MCP**。
3. **是不是人对事实的取舍/判断?**(真伪、边界、拍板)→ 是 → 落 **prompt**,并把答案记录进三区表。
4. **是不是企业控制面已经管的?**(账号/审批/发布/审计/模型网关)→ 是 → **接入它,不另造、不绕过**;代码里只保留必要的校验与幂等。

## 三个例子(判定三问怎么用)

1. **「数据不能出客户机器」** → 问 1:能机械检查吗?能(脚本只读写白名单目录,写外部路径直接报错;网络出口白名单)→ **代码**;同时 G4 记录为硬约束(prompt)。
2. **「取飞书需求文档」** → 问 2:需要外部系统吗?是 → **CLI**(`lark-cli docs +fetch`);有 MCP 服务用 MCP。
3. **「这需求真伪」** → 问 1 不能、问 2 不是 → **prompt**,结论进 G2 过目。

## CLI vs MCP:业务场景对照与利弊

> 一句话原则:**CLI 是「机器上的一条命令」,MCP 是「Agent 的受控工具接口」。** 能用现成 CLI 就别造 MCP;出现「复用压力 / 凭证隔离 / 风险护栏」任一信号,MCP 才值得。

### 五轴判定(按顺序问)

| 轴 | 问 | CLI | MCP |
|---|---|---|---|
| 使用者 | 谁用? | 人和 Agent 都要用(同一条命令) | 只有 Agent 用 |
| 频率 | 用几次? | 一次性 / 低频 / 批处理 | 会话内高频、参数多变 |
| 宿主 | 几个 Agent 客户端? | 单机单宿主 | ≥2 个宿主 / 多次会话复用 |
| 凭证 | 凭证能给 Agent 看吗? | D0 可以(本机环境变量);D1/D2 只在批准机器/secret manager | 不能(server 集中持证) |
| 风险 | 读还是写? | 只读、低风险 | 写 / 删除 / 生产环境(要护栏) |

### 利弊对照

| | CLI | MCP |
|---|---|---|
| 利 | 零/低成本(现成工具如 lark-cli);可复现、可写进 SOP;人和 Agent 通用;易调试 | 标准协议跨宿主;typed schema 自动校验(参数错一次就省一次上下文);凭证集中不泄露;服务端 guardrails 挡高危错;工具可发现、错误结构化 |
| 弊 | 无 schema(参数错靠 prompt 反复试);凭证自理;模型要记命令语法(占上下文、易拼错);多客户端各自配置 | 开发/部署/运维成本(写 server、版本、监控);多一层故障点(server 挂=全断);简单任务过重;调试链路长 |

### 业务场景对照(按场景选)

| 场景 | 选 | 为什么 |
|---|---|---|
| 读一份飞书需求文档 | CLI | `lark-cli docs +fetch` 现成,一次性;MCP 过重 |
| 每天定时跑日报批处理 | CLI + cron | 无会话无人交互;MCP 服务的是会话内调用 |
| 会话内反复查/写多维表格 | 高频→MCP;低频→CLI | 高频参数化吃 schema 红利;低频单宿主 lark-cli 够 |
| 多个 Agent(DSH + Claude Code)共用客户数据 API | MCP | 标准协议跨宿主,一次部署到处可用 |
| 客户 API 凭证敏感 | MCP | server 持证,Agent 全程不碰(呼应 auth-permission.md) |
| 写/删除/生产环境操作 | MCP(护栏)或 CLI+代码白名单 | 高危必须 schema+guardrails,或至少代码兜底 |
| 一次性数据清洗 | 脚本(code) | 不是 CLI 也不是 MCP |
| 真伪判断/约束分区 | prompt(元技能) | 工具层没有判断 |
| 只有人用的操作 | CLI | 人不用 MCP |
| F1 薄切片验证期 | CLI/脚本 | YAGNI:先验证切片,后谈复用 |
| 无 API 只有人工导出 | manual | 人肉桥,标 ⚠️,走预案 |

### 过早 vs 过晚

- **过早**:切片没验证就封 MCP → 白付维护成本(违反「先正确后扩展」)。
- **过晚**:同一个 API 被 3 个 agent 各自 CLI 裸调、凭证散落各处 → 该封 MCP 了。
- **信号**:F1 验证过 → F3 稳定用 → 出现「第二个宿主」或「凭证隔离需求」→ 封 MCP。

## MCP 决策清单(快速版,场景对照见上节)

判定三问(≥2 个「是」→ 做 MCP;只有 1 个 → CLI/脚本):

1. **跨 Agent/客户端复用吗?** 同一能力服务多个宿主(Claude Code/DSH/IDE 插件)或多个会话反复调 → MCP 候选;单机单 agent → CLI 够。
2. **凭证要隔离吗?** key/token 存 server 侧、agent 全程不碰 → MCP 候选(凭证集中+按客户端裁剪权限,如只读 server)。
3. **需要 schema 护栏吗?** 写操作/生产环境/删除类,typed input + 服务端 guardrails 挡错 → MCP 候选。

**不该做**:一次性 → 脚本;固定批处理 → cron/CLI;判断取舍 → 元技能(prompt,MCP 只会执行不会判断);只有人用 → CLI/GUI。

**升级路径**:F1 薄切片用脚本 → F3 现场工具用 CLI → F5 复用期且跨 agent/凭证隔离/护栏需求出现 → 封 MCP。**F1 阶段不做 MCP**(YAGNI:切片未验证先建抽象,违反 code-first-principles「先正确后扩展」)。

**制品定性**:MCP 是「工具层成分」,不是元技能也不是工作流本身;工作流 skill 的执行步骤可以调 MCP 工具,图谱节点标 `[mcp]`。

## 纪律

1. 硬约束(授权/鉴权/密钥/数据边界)至少一层代码兜底;只有 prompt 的硬约束 = 没约束。
2. CLI/MCP 步骤必须可复现(命令写进 SOP,不是「大概跑一下」)。
3. prompt 层产出的每个判断,都要在计划书里落成可检查的字段(出处列/三区表/定性栏)——判断不可检查 = 无效判断。
4. 先定层再动工:图谱节点标注完成前不写代码。
5. D1/D2 的控制面不可绕过:不在白名单就换方案/交 F2,不得「先跑通再补审批」。
