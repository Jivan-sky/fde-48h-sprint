# Agent 执行书:把已批准的计划书变成有边界的施工单

> Phase 7 产出,Phase 10 交给实现 Agent。它不是新计划,不替代 G4/G5,也不构成写许可。
> 一句话:**执行书只定义「这一次做什么、做到什么程度、绝对不能做什么」,不定义「顺便把平台也做了」。**

## 1. 什么时候用

| 场景 | 用不用 | 说明 |
|---|---|---|
| 计划书已过 G5,进入 M0/M1,要交给另一个 Agent 或工程同学实现 | 用 | 执行书是交接合同 |
| 需求还在辨真伪、计划书没过 G5 | 不用 | 先回 Phase 2-7,不要用执行书掩盖未决问题 |
| 要写客户系统 | 用,但先过 G3/G6a 和 `write-gate-record.md` | 执行书不是写许可 |
| 只是现场口头演示、不交接 | 可不用 | 仍受执行边界卡约束 |

**执行书不能扩大计划书范围。** 新增范围、换切面、加平台/后台/权限体系 → 回 G4/G5 重签字,不在执行书里“顺手加”。

## 2. 必须写清的 13 组字段

| # | 字段 | 必须写什么 | 缺失时 |
|---|---|---|---|
| 1 | 身份与版本 | `execution_id`、计划书版本/哈希、部署模式 D0/D1/D2、阶段 M0/M1 | 不执行 |
| 2 | 目标 | 一句话、可验证的业务结果;不是“做个系统” | 不执行 |
| 3 | 薄切片 | 一个真实输入 → 一个动作 → 一个输出;输入从哪来、谁用 | 不执行 |
| 4 | 明确不做 | 平台、后台、全量接入、权限体系、模型微调等逐条列出 | 不执行 |
| 5 | 环境与访问 | 环境、入口、账号性质、网络路径、工具/模型白名单、允许安装什么 | 不执行 |
| 6 | 数据合同 | 数据源、分级、样本来源/批准记录、驻留、留存、能否出网/进模型 | L3/L4 未批准 → 停 |
| 7 | 动作边界 | 当前阶段最高允许动作(A/B/C)、明确禁止清单、未知风险怎么办 | 不执行 |
| 8 | 接口/数据契约 | API/CLI/人工桥、鉴权、字段、分页、错误、权限、限流 | 对应项标“未取得”,不得猜 |
| 9 | 写路径 | M0 必须写“无”;M1 起链接 `write-gate-record.md` 与变更号,并列出对象键/主键映射、逐对象 before-image URI、`INSERT/UPDATE/DELETE` 各自补偿动作 | 无卡、无 before-image 映射不写 |
| 10 | 验收 | 每项验收的命令/动作、预期输出、谁验、证据放哪 | 不验收 |
| 11 | 证据与台账 | 记录什么、`operation_id`、存放位置、保留期、谁可查 | 不执行 |
| 12 | 停机与升级 | 什么条件停、停谁、怎么通知、是否回滚、谁决策 | 不执行 |
| 13 | 回交 | Agent 完成后必须交回:改动文件、运行命令、证据、未决问题、残余风险 | 不算完成 |

## 3. M0 执行书硬约束

1. **生产写入 = 0,共享测试环境写入 = 0。** 需要写才能演示 → 改只读/一次性可重置沙盒/人工桥。
2. **只用一个切片、一个真实动作、一个可验证输出。** 不做平台、管理后台、全量接入、权限体系。
3. **只用客户批准的环境、账号、工具、模型。** 不装未审批工具,不绕白名单,不借账号。
4. **只用批准的数据。** 真实单据最好;否则用客户批准的脱敏/合成样本,并标明来源与限制。
5. **卡点 >4h 换切面或停。** 不靠加班、不靠“再试一次”、不靠扩大范围绕过。
6. **Agent 不能运行时**,改为“本人交付可审查制品 + 客户授权人员执行 + 本人验证输出”;标执行人与证据,不得声称自己跑过。

## 4. 状态机与停机

```text
draft → approved → executing → blocked → verifying → accepted
                                      ↘ rejected
                                      ↘ rolled_back
```

| 状态 | 进入条件 | 谁能改 |
|---|---|---|
| `draft` | 执行书初稿 | Agent/开发者 |
| `approved` | 计划书过 G5;G6a 已授权;范围和边界签字 | 开发者 + 客户控制角色(按模式) |
| `executing` | 环境/数据/账号到位;验收命令可运行 | Agent |
| `blocked` | 权限、数据、环境、审批、风险任一卡住 | Agent 只能报,不能自批 |
| `verifying` | 切片完成,开始跑验收 | Agent + 验收人 |
| `accepted` | 验收命令通过 + 证据归档 + 人签字 | 验收人/业务 owner |
| `rejected` | 验收失败或价值不成立 | 验收人 |
| `rolled_back` | 触发回滚并完成 read-back | 回滚决策人 |

**Agent 不得自行把 `blocked` 改成 `executing`,不得自批、自验、自回滚。**

## 5. 验收必须可执行

每条验收都要有命令或明确的人工动作,以及预期输出。禁止“应该能跑”“看起来正常”。

| 验收 ID | 验什么 | 命令/动作 | 预期输出 | 证据 | 谁验 |
|---|---|---|---|---|---|
| AC-1 | 示例:切片对一张真实单据输出正确字段 | 运行客户批准的命令/脚本 | 输出字段齐全、值与单据一致、无多余字段 | 命令输出 + 单据编号 | 一线/业务 owner |

规则:

1. 命令必须是客户环境里实际可执行的;不能执行的写“人工步骤”,并写谁执行。
2. 预期输出要具体到字段、数量、状态或页面结果,不能只写“成功”。
3. 失败样本也要留:空结果、权限失败、超时、格式异常。
4. 验收证据只放索引;原始敏感证据留在客户受控系统。

## 6. 与计划书/门禁的映射

| 执行书字段 | 来自计划书 | 门禁 |
|---|---|---|
| 目标/切片/不做 | §9 | G5 |
| 阶段/范围/退出条件 | §10 | G5/G6a/G6b |
| 数据合同 | §6 | G3/G4 |
| 控制面/写前基线 | §11 | G6a/G6b |
| 验收/证据 | §13 | G5/G6b |
| sniffer 探查结论 | 附录 D | G3 |
| 写路径 | §11 + `write-gate-record.md` | G6a/G6b |

## 7. 最小结构(按标题写,不留空)

1. 身份与版本
2. 目标与价值假设
3. 薄切片(输入/动作/输出/使用者)
4. 明确不做
5. 环境、账号、网络、工具/模型白名单
6. 数据合同与样本来源
7. 动作边界(A/B/C + 禁止清单 + 未知风险)
8. 接口/数据契约与人工桥
9. 写路径(没有就写“无”)
10. 验收用例与命令
11. 证据、台账、保留期
12. 停机、升级、回滚
13. 回交清单

**每一节都必须有真实内容或“不适用 + 原因”。留空、写“待补”、写“参考计划书”都不算执行书。**

## 8. 反模式

1. 把计划书原文复制一遍,当成执行书。
2. 只写“按计划书执行”,不写具体输入、输出、命令、验收。
3. 用“完成后再说”代替验收标准。
4. M0 执行书里出现生产写入或共享测试环境写入。
5. Agent 自行扩大范围、换技术栈、装未审批工具。
6. 没有停机条件,卡住就无限重试。
7. 没有回交清单,做完只留一句“已完成”。
8. 把执行书当写许可,跳过 `write-gate-record.md`。
