# sniffer → FDE 交接契约:G3 只接收可核的只读判断

> Phase 4 / G3 用。`web-capability-sniffer` 的产出是**判断上下文**,不是写许可,也不是可直接执行的接口清单。
> 一句话:**报告里的每个结论都要能追到动作、证据和风险边界;追不到就不进 G3。**

## 1. 必须收到的材料

| 材料 | 用途 | 缺失时 |
|---|---|---|
| 报告 ID、版本、时间、目标范围 | 绑定本次探查与后续变更 | G3 不通过 |
| 逐动作审计日志 | 证明探索写操作=0、B/C 只识别 | G3 不通过 |
| 功能地图 / Flow / Step / Evidence | 业务理解与 CLI 候选 | G3 不通过 |
| 接口清单、鉴权方式、权限要求 | 判断直连/人肉桥/不通 | 对应能力标“未知”,不得设计写 |
| 数据模型/字段/枚举/状态机 | 设计输入与校验 | 对应字段标“未取得” |
| 可追溯/可回滚矩阵 | 判断能否进入 M1/M2 | 写风险能力缺行 → G3 不通过 |
| 盲区、未执行动作、停止原因 | 防止把推断当事实 | G3 不通过 |

## 2. 验收硬条件

报告必须同时满足:

1. `探索阶段写操作执行：0`;`写操作执行清单：无`;`生产副作用：0`。
2. `授权是否改变执行边界：否`;报告明确“授权只扩大记录范围,不扩大执行范围”。
3. 有逐动作审计日志;所有 B/C 动作的执行状态为“未执行”;没有手工请求、请求重放、HAR 导出、主动扫描、越权探测。
4. 每个写风险能力和每个 `未知风险` 能力都有一行可追溯/可回滚评估。
5. `未知风险` 没有被标成 `已验证 API`、`可重放`、`只读安全` 或可直接封装的 CLI。
6. 写风险能力的 CLI 适配只能是 `待受控交付` 或 `禁用占位`;不得出现写脚本、写命令示例或“先调一下看看”。
7. `CLI适配=是` 的能力必须是只读安全或已定义的敏感查询,且方法、路径、参数、响应、权限、数据敏感级别都有证据。
8. 报告区分 `runtime_observed`、`user_confirmed`、`repository_artifact`、`document_clue`、`hypothesis`;页面/菜单/路由存在不得写成已验证 API。
9. 运行时写保护声明必须给出 guard 位置/版本、`allowReadPostPaths` 与 `allowSessionPostPaths` 的具体值、每个精确路径的 owner 确认、阻断次数;通配符/前缀白名单、把登录混入只读白名单 → G3 不通过。
10. 阻断事件只记录脱敏 `origin + pathname`,不含 query/body/header、邮箱、长 ID 或凭据;路径脱敏和弹窗文案脱敏缺失 → G3 不通过。

## 3. 进入 FDE 后的映射

| sniffer 结论 | FDE 动作 |
|---|---|
| `只读安全` + 高证据 | 可作为 M0 输入或 M1 只读数据流候选 |
| `敏感查询` | 先过数据分级/最小字段/审计;不得默认全量输出 |
| `可写但需快照` | 只能进 M1 测试环境写入设计;填 `write-gate-record.md` |
| `可写但需审批` | 只能进 M1/M2 受控设计;补审批、SoD、回滚、read-back |
| `不可写` | 只读、人工执行或换切面;不得设计自动写 |
| `未知` / `未知风险` | 只读/禁用占位;补证前不得进入写入设计 |

## 4. 明确不接受

- “报告已生成”当作 G3 通过;必须逐项核验收硬条件。
- 把页面按钮、菜单、路由、静态代码当成已验证 API。
- 把客户口头授权、管理员账号、共享账号当成写许可。
- 用“只读 POST”“先请求一下”“只导出一次”绕过只读边界。
- 用 `/api/*` 之类前缀白名单代替逐端点确认,或把登录 POST 当作只读查询放行。
- 写风险能力标 `已验证 API`、`可重放`、`只读安全` 或 `CLI适配=是`。
- 用补造证据、提高置信度、删除盲区来通过校验。

## 5. 交接后的第一件事

在计划书 §6 写清:探查报告 ID/版本、每个数据流的可追溯/回滚结论、未知项、哪些能力只能只读、哪些需要 `write-gate-record.md`。**没有这些,FDE 不得进入 Phase 5 的方案设计,更不得进入 M0 写入。**
