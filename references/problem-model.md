# 问题模型:勘探的产出物是问题模型,不是一堆笔记

> Phase 2 用。**来源**:HA7CH / Lawted 公开讲义《勘探的产出物是问题模型》(转述,非原文)。
> 一句话:**Echo 的产出物就是问题模型。** 第 1 课说 FDE 拥有"问题定义权",问题模型就是那个"定义"的载体;没有它,问题定义权是一句空话。

## 五个要素

| 要素 | 回答什么 | 反面(不合格) |
|---|---|---|
| **核心瓶颈** | 真正卡住经营结果的是哪个具体环节? | 直接抄客户原话;或写成"没有系统" |
| **因果链** | 为什么会卡:至少三条,标 技术/流程/外部/能力 | 只写现象不写原因;或原因全归到"没有系统" |
| **量化影响** | 这个瓶颈让客户损失了什么:时间、收入、满意度;能度量吗? | 用员工口头估计**冒充实测**;劳动时间与等待历时混在一起 |
| **相关方地图** | 谁被影响、谁有动力推动、谁会**阻碍**改变;谁是**主裁**、谁是**盟友** | 只画支持者不画阻碍者;分不清主裁和盟友 |
| **已有尝试** | 客户之前试过什么、为什么失败 | 完全不问,然后把失败过的方案再做一遍 |

**好的问题模型能穿过表面表述**:
- 客户说"客服压力大" → 问题模型说"八成咨询集中在三个高频问题,其中两个可用知识库解决"。
- 客户说"数据分析效率低" → 问题模型说"数据散在四个系统,每周手工导出合并、人工核对一致性"。
- 老板说"要 AI 全自动" → 问题模型说"跟单员每天肉眼对单、做账最烧脑最赔钱,该做轻量增量插件,不是重做 ERP"。

## 与三道探针的关系

- **假需求题** 关联 **核心瓶颈**。
- **经济账题** 关联 **量化影响**。
- **薄切片题** 测 **Echo + Delta**——能否把真实问题做成让一线当场验证的最小产物。
- **"已有尝试"** 是这里补充的访谈项,**不能用它替代薄切片题**。

## 带状态的活文件(诊断期怎么用)

问题模型不是一次写完的文档,而是**带状态的活文件**:

1. 每个要素带 `状态: 假设 / 已验证 / 已推翻` 和证据链接(访谈纪要/数据表/流程文件)。
2. **老板访谈只给假设;逐人访谈(含一线)给证据。**
3. 第一批要做的工具和 bot,每个回指问题模型的一个要素(例:"把采购周报还原成任务级甘特图"对应"管理层看不到任务级进度")。
4. 每个里程碑复盘**先看哪些假设变成已验证/已推翻**,再谈交付;推翻的要素改问题模型,**不改方案 PPT**。

## 粒度随客户层变(与九宫格联动)

- **第一层(30 人)**:一个核心瓶颈 + 一条因果链就够。
- **第二层(200 人)**:要画到跨部门的**相关方地图**。
- **第三层(国央企)**:相关方地图本身就是一份**交付物**。

## 模板(可直接复用)

```
# 问题模型 v1 · <客户/场景>

## 核心瓶颈
<一句话,落到具体环节>   状态:假设/已验证/已推翻   证据:<链接>

## 因果链
1. <原因> —— 类型:技术/流程/外部/能力   状态:…   证据:…
2. ...
3. ...

## 量化影响
| 数字 | 谁说的 | 估计/实测 | 证据级(L1/L2/L3) |

## 相关方地图
| 角色 | 立场(推动/中立/阻碍) | 动机 | 主裁/盟友/阻碍者 |

## 已有尝试
<试过什么、为什么失败、这次有什么不同>
```

## 自检

五个要素齐;**核心瓶颈不是老板的原话**;**量化影响里没有一个未标来源的数字**;**相关方地图里至少有一个阻碍者**。
写不出核心瓶颈 = 通常是在访谈里被细节漩涡带走了——这比任何评分都更早暴露问题。
