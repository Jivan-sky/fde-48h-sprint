# 写入门卡:每次写客户系统前的一张可检索记录

> Phase 9/10、G6a/G6b 用。适用于测试环境、共享环境、灰度和生产;M0 默认不使用本卡,因为 M0 不写客户系统。
> 一句话:**没有这张卡,不进入执行;卡上有任何一项“否/未取得/未演练”,就不写。**
>
> 本文件是**运行时记录模板**：尖括号字段必须由执行人填入可核验的真实值；保留模板字样、留空或只写“有快照/已演练”而没有 URI、哈希、时间和审批记录，均按“未取得”处理，禁止写入。

## 8. 硬规则

1. 第 1-23 项任一为“否/未取得/未演练” → 不执行；第 24-25 项未完成 → 不算结案，不得开下一批。
2. 测试环境也要填本卡;只有可重置、可丢弃、无外部副作用的一次性沙盒,才允许把“快照”简化为“重置证据”,但仍要留影响范围、清理和 read-back。
3. 写后快照缺失、read-back 不符、台账不可用 → 立即停止后续批次,按事故处理,不得补造证据。
4. 回滚本身按本卡重新执行;默认行级补偿,全表/分区/PITR 恢复必须先冻结并发写入并盘点快照后的合法写入;紧急回滚按预先批准的 runbook 执行,不能由 Agent 临场自创。
5. 本卡不能替代客户变更单/审批;客户变更号必须回填。
6. 目标业务表没有 `operation_id` 字段时，不得假设可查询回滚；必须用 `operation_change_item` 记录对象键与 before-image 映射。
