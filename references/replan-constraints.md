# 重规划提案 + 约束三区

> Phase 6 用。目标:把「流程哪里要改」摆到人面前,人点头才改;人不点头的部分,原样保留并升格为**硬约束**。改与不改,永远分区记录(纪律「约束分区」)。
>
> **D1/D2 追加**:控制类约束(数据边界/生产权限/三权分离/审计/工具与模型白名单/变更发布)默认是硬约束,不是「建议」。可以优化控制实现,不能由 Agent 取消控制。

## 提案模板(每个红标节点三选一)

```
节点 X(证据:月错 2 次)
A. 保留不动 —— 这是硬约束(合规/签约/拍板),原样保留
B. 绕过 —— 不动原流程,切片在它旁边加一道检查/辅助,不碰它
C. 砍掉/替换 —— 直接重规划这一步(换接口/换数据源/换顺序)
```

## 问人话术(选择题带理由)

```
Q: 这个流程可以重新规划吗?
A. 整条可以重规划 —— 按最省人工的路径来,旧步骤全部可动
B. 部分不能动 —— 哪几步不能动?我标成硬约束,其余重规划
C. 完全不能动 —— 现状流程我原样画进图谱,切片只做「不碰现状」的最小切口
```

## 三区表(计划书第 6 节固定格式)

| 区 | 含义 | 记录内容 | 变更规则 |
|---|---|---|---|
| 硬约束 | 不可动 | 业务硬约束 + 控制类硬约束(数据/权限/SoD/审计/白名单);谁定的 + 为什么 + 影响范围 | 只能由客户授权角色书面解除;解除后回退重规划 |
| 假设 | 未验证,按真处理 | 依据(文档/口头)+ 验证方式 | Sprint 中被推翻 → 回 Phase 5-6 重规划 |
| 决策 | 双方确认的选择 | 决策人 + 时间 | 可改,但必须重新过 Phase 5-6 |

## 人不肯重规划时的降级路径

1. 现状流程**原样**画进图谱(不做「优化版」);
2. 所有「不能动」节点升格硬约束,列明谁定的;
3. 切片围绕硬约束外的**最小切口**设计(比如只做「导出后的核对」,不碰导出本身);
4. 计划书第 6 节写清:本次未重规划,以下为硬约束——给下一轮留口子。

## 控制类硬约束(D1/D2 必过)

1. **不能砍控制**:审批/权限/审计/发布控制只优化实现(自动审批、预授权、只读、抽样审计、批量替代交互),不能取消。
2. **最小必要控制集**:逐条问「解决什么风险?去掉会怎样?有没有更轻的实现?」;去掉必须由客户 I/S/R/O 书面确认。
3. **三权分离**:开发者不能自批、自发、自审;FDE 不替客户补角色。
4. **控制成本与运行成本**:审批等待、安全/隐私评估、审计、变更、回滚、培训,以及模型/API/推理、存储、向量库、监控/值班进经济账;不藏进「节省工时」。
5. **控制证据**:每条控制有 owner、证据、保留期;没有证据 = 未验证。

## 三区的确认门(G4)

1. 三区表逐条读给开发者听;**业务硬约束每条必须开发者/客户拍板人亲口「是」;控制类硬约束必须由客户 I/S/R/O(涉及证据加 Aud)书面确认,开发者点头不能替代**。
2. 「没人反对」≠「同意」;点头(口头签字)后才算成立。
3. 硬约束只能由客户授权角色书面解除;Agent 不得自行把硬约束挪到决策区。
4. 中途出现新约束 → 回 Phase 5-6 重分区,并重新过 G4。
5. 文档不清时,「没写的约束」按「待确认」处理并进提问清单,不默认成「没有约束」。
6. D1/D2 控制角色缺失/未确认 → 停在 G4,不进 Phase 7。

## 纪律

1. 三区**绝不混写**:同一件事不能既在硬约束又在决策区。混写 = 负面检查命中,停修。
2. 「没人说不能改」≠「可以改」:拿不准就问,别替人拍板。
3. 每次人补充新约束 → 回 Phase 5-6 重新分区(纪律「约束分区」的连锁)。
4. 不得把「控制类硬约束」挪进决策区来换取进度;这是控制面绕过,停。
