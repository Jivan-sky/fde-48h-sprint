# 提问模板:业务真伪信息缺口 → 预设问题

设计原则(来自 DESIGN.md 洞察 2+3):缺口可预测 → 预设模板;人的决策成本必须低 → **选择题带理由**,不用开放填空。每次提问 ≤3 题,一题一轮,答完复述确认。

## 缺口 → 模板对照表

| # | 缺口 | 出现概率 | 提问模板 | 二级追问 |
|---|---|---|---|---|
| 1 | 谁拍板 vs 谁在用 | 90% | 这东西是给谁**天天用**的,还是只给领导**看一次**的? | 天天用的人坐哪?几点用? |
| 2 | 天天做错被骂的具体事故 | 85% | 最近一次做错/返工/被骂是哪次?因为什么? | 做错之后谁擦的屁股?花了多久? |
| 3 | 数据源真实性 | 80% | 有没有**真实单据**?长什么样?在哪? | 后台能导吗?谁有权限? |
| 4 | 经济账数字来源 | 75% | 这个预算/收益数字是**谁算的**?有依据吗? | 砍掉哪个动作省了这些工时? |
| 5 | 机会点线索 | 70% | 你听过他们说「要是能…就好了」吗? | 原话是什么?对着哪个动作说的? |
| 6 | 动作频率 | 60% | 这个动作**多久一次**?每天/每周/每月? | 一次花几分钟?几个人做? |
| 7 | 谁有数据权限 | 50% | 数据在谁手里?你能拿到吗? | 导出的格式是什么?截图/表格/PDF? |
| 8 | 明确不做边界 | 45% | 这活做完,**绝对不能**碰什么? | 之前有人尝试做系统失败过吗? |
| 9 | **已有尝试(谁做过、为什么失败)** | 70% | 这活之前**试过什么**吗?谁做的?最后为什么没成? | 是方案不行、人不行,还是当时时机不对? |
| 10 | **入口经济学(真正操作者)** | 70% | 这个单据/动作,**真正动手的是谁、几个人**? | 他们是长期在这个岗,还是换人很频繁? |

> 缺口 9、10 是 v3 新增的两道**闸**。缺口 9 不问 = 把客户失败过的方案再做一遍;缺口 10 不问 = 默认「上 OCR」或默认「让全员改用新工具」,两种默认都可能错(见 `references/field-discipline.md` 第十节)。

## E 组:销售 / BD 必答(Echo 甄别,硬规则)

如果传需求的人**是销售/BD,不是真正下场的 FDE**,先答这一组。**答不出 → 标「销售话术型」;他给的需求真伪、机会点、经济账结论一律降级为「线索 L3」,不进计划书正文。**

| 题 | 问什么 | 合格的答法 |
|---|---|---|
| E1 | 举一个**当面否掉老板预期**的真实案例:哪个老板要 A,你劝他改成更小的 B,后来成了? | 有具体的人/事/结果,不是「我们一般都是这样」 |
| E2 | 有没有过**劝客户先别签单**(或先别做)的经历?为什么? | 有,且能说清省掉了什么风险 |
| E3 | 最近一次听到一线抱怨,**原话**是什么?谁说的? | 能复述原话 + 指名角色,不是「他们反映…」 |
| E4 | 这个预算数字,是客户自己说的,还是你算的?算给谁看过? | 能说清数字来源与核对方式 |

**判据**:E1/E2 答不出,或全部答案都是「顺着客户/顺着老板」→ 判 **销售话术型**。此时:可以继续聊,但他给的一切判断都要自己下场核过才写进计划书。

## 使用规则

1. **按缺口匹配模板**,别全问。采矿笔记里哪个缺口已填,就跳过对应模板。
2. **每轮 ≤3 题**,选择题带一句理由,让人秒答:
   - 坏:这需求真伪如何?
   - 好:这东西是给运营天天用的,还是给老板做汇报看一眼?——分清楚这个,决定我们做不做、做成什么样。
3. **答完复述确认**(Echo 压缩版):你刚说的是「运营每天 18 点手工整理后台导出」,对吗?
4. 人答出新信息 → 记入采矿笔记,可能触发新机会点。

## 选择题格式(每题强制带理由)

```
Q: <问题>
A. <选项 1> —— <为什么是这个答案>
B. <选项 2> —— <为什么是这个答案>
C. 都不是 / 说不清
```

示例:

```
Q: 这个需求是给谁用的?
A. 运营自己天天用 —— 那痛点是真的,做成工具值得
B. 给老板看一次汇报 —— 那是演示,不是 FDE 产物,价值存疑
C. 都不是 / 说不清
```

## 回退规则

- 人中途补充新约束 → 回 Phase 2 重采矿(新约束 = 新问题模型要素)
- 人对真伪判断有异议 → 回 Phase 3 重新核验(你判断「真」但他质疑证据 → 换证据链)
- 人答出「之前试过、失败了」→ 回 Phase 2 补问题模型「已有尝试」要素,并考虑是否直接转 F2
- 连续 3 轮用户都答「说不清」→ 停,告诉用户「信息缺口太大,建议先下场摸一天」,交付 F2 一页纸真伪结论。

## 采矿笔记 → 提问优先级

读采矿笔记,优先问**证据最弱**的缺口(信息缺口大 = 判断最不可靠):

```
证据强(文档明确写了) → 只确认,不问
证据中 → 选择题确认
证据弱/无 → 必问,这是风险点
```

例:文档写了「运营每天手工整理」但没写「做错被骂」→ 缺口 2 必问;文档写了「老板要平台」但没写谁在用 → 缺口 1 必问;文档写了「之前上过系统」但没写为什么废了 → 缺口 9 必问。
