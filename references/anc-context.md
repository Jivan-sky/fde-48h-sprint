# ANC:这一刀落在树干上的哪一格

> **只在路线 B(ANC 架构)读**;选路线 A(FDE 交付)不必读。Phase 1 与 Phase 9 用。**来源**:HA7CH 公开材料与 ANC 系列 Skill(camp.ha7ch.com、anc-diagnosis、ha7ch-home 公开 SKILL、产品资料)——**转述,非原文**,项目状态以对方当前口径为准。
> 一句话:**具体工具是叶子,ANC 是树干。** 48h 做出来的东西是叶子;叶子必须接回树干,否则每一刀都从零开始。

## 一、ANC 是什么

**ANC 是一层共享的 AI 运行层**,把企业的**业务上下文、任务、人、Agent、权限**连在一起,让每一次交付都不只是一次性工具,而是强化同一套底座。

它连接七样东西(缺一样,叶子就挂不上去):

| 连接件 | 是什么 | 48h 里对应什么 |
|---|---|---|
| **Context** | 企业的人、角色、项目、客户、产品、当前状态、对话、文件、决策、例外 | Phase 2 采矿与问题模型;Phase 9 写回 |
| **权限** | 谁能看什么、能改什么、能执行什么 | Phase 0/7 数据与权限边界 |
| **Skill** | 完成可重复工作的固化能力 | Phase 9 沉淀的脚本/Skill |
| **人** | 角色、责任、DRI/IC 分工 | Phase 1 一号位;Phase 7 双方负责人 |
| **Agent** | 实际干活的智能体 | Phase 8 本人端到端的那套东西 |
| **动作** | 任务怎样被触发、执行、交接 | Phase 6 薄切片输入→处理→输出 |
| **反馈** | 结果、纠错、例外如何回流,改进下一次执行 | Phase 9 沉淀线 + 每轮复盘 |

## 二、树叶与树干(为什么必须写回)

- **叶子** = 具体应用:抽 PDF 字段、出报价、库存视图、跟单、项目看板、一个小 SaaS。叶子解决**眼前问题**。
- **树干** = ANC 保留的东西:人/角色/权限、项目/客户/产品/状态、对话/文件/决策/例外、可复用 Skill、**任务-负责人-证据-下一步**的关系、改进下一次执行的反馈。

**关键判断**:一片叶子做完,如果只留下一个脚本、没把它的**上下文、权限、Skill、反馈**接回树干,那么下一个需求还要重新问一遍同样的问题。**这就是 Phase 9 存在的理由。**

## 三、企业的运行结构词汇(判层和建模时用)

ANC 把企业拆成可被 Agent 理解的结构:**Project(项目)/ DRI(直接负责人)/ IC(参与贡献者)/ Task(任务)/ Context(上下文)/ permissions(权限)/ responsibilities(责任)/ result evidence(结果证据)**。

- 判客户层时,先问:这家的 **Project** 是什么?**DRI** 是谁?任务有没有**结果证据**?——问不出来,说明还没找到 ANC 的接入点。
- 问题模型里的「相关方地图」,落到 ANC 就是 **DRI 与 IC**:谁是 DRI(拍板+担责),谁是 IC(具体干活)。

## 四、现场交付的两种形态(HA7CH 的现场口径)

- **ANC-Diagnosis(一点一面)**:团队进企业现场 5 个工作日,和老板、业务负责人、一线分别对齐,最后给老板「**一面企业 AI 全景图 + 一点真实 Demo**」,并给三种结论之一:**GO / HOLD / NO-GO**。
- **一阶段 = 调研 + 基线 + 可视化**:不是先做功能,而是先把「现状工作怎么发生、卡在哪、怎么衡量」变成可看的东西(如把历史周报还原成任务级甘特图),再谈下一步。
- 内部培训**不是默认第一步**:先完成一个具体优化,等企业要推广新工作方式时再用培训收口。

> 你的 48h Sprint 相当于把 Diagnosis 的「一点」压到极致:不加全景图,先用**一个真实单据**证明「这能帮到一线」。全景图与 GO/HOLD/NO-GO 的判断,可以借 Phase 6/7 的停止条件与 POC 一页纸承接。

## 五、FDE = Echo + Delta(ANC 的入场条件)

`FDE = Echo + Delta`,缺任一半都不是 FDE:

- **Echo**:进真实现场,摸出真需求,**主动推翻**老板/甲方的表面需求;分清「谁拍板 ≠ 谁在用」。**按需求文档拆解、承接甲方需求、为签单顺着老板预算走,都不是 Echo。**
- **Delta**:本人主导、**零依赖端到端**把能跑的东西做出来(输入→处理→输出全链路)。**用 Codex / Claude Code 端到端做出来,是合格 Delta。**

**硬地板(交付物要同时满足三条)**:

1. **端到端**:真实输入(真单据/真数据,不是 toy)→ 处理 → 可见输出,本人主导;
2. **可运行**:现在能演示能跑,不是 PPT / 规划中;
3. **被外部一线验证过**:**非本公司员工 / 真实客户 / 一线现场用户**用过,或能当场当着非技术的外部使用者拖真实单据。

> **纯企业内部系统、面向本公司同事的工具,默认不满足第 3 条**——内部同事用过 ≠ 被验证。这是 3 条里最容易被自我安慰掉的一条,也是 Phase 6 校验要盯的。

## 六、五条现场真相(ANC 反复强调的)

1. **反平台是生死线**:AI 增量插件 / 数字员工 / 蒸馏现有工作流,不是换系统、重做 ERP、上中台、搭低代码底座。
2. **经济账自己算**:用「砍掉人力工时 × 单位成本 × 10-20%」重算,不信老板拍脑袋,也不为签单顺着报。
3. **价值在一线,不在拍板主管**:真正被解放的是一线高频用户,价值证据去一线找。
4. **入口也要算经济账**:先数真正操作新入口的是谁、几个人,再比较改习惯与做适配层的总成本;不默认 OCR,也不默认全员开新工具。
5. **护城河是领域正确 + 端到端落地**:在线填表 / 发链接 / OCR / 扫码录入这些早就存在,当杀手锏=扣分。

## 七、在 Sprint 里怎么用这份文件

| 阶段 | 用 ANC 做什么 |
|---|---|
| Phase 1 分层 | 用 Project / DRI / IC / Task 词汇问清客户运行结构,判断接入点 |
| Phase 3 提问 | 硬地板第 3 条(被外部一线验证过)用来判定「验证标准」够不够硬 |
| Phase 6 校验 | 复查薄切片是否满足端到端 / 可运行 / **被外部一线验证过** |
| Phase 7 沟通 | 「一点一面」:先给一点 Demo;全景图与 GO/HOLD/NO-GO 用 POC 一页纸承接 |
| Phase 9 沉淀 | **把这次结果接回树干**:这条上下文、这个权限、这个 Skill、这条反馈,分别写回哪里 |

## 八、维护口径(v3.2 决定)

- **不做独立载体。** ANC 作为本 skill 的**路线 B** 存在,与路线 A 平级、入口统一;不提前新建仓库或独立 skill。
- **唯一维护源 = 本文件**(`references/anc-context.md`)。Agent 侧读 ANC,以此为准。
- 知识库里的 ANC 文档(`ANC架构设计大框` / `ANC本土落地案例库` / `ANC架构总纲`)是**人的资料**,不在这里重复维护;两边若出现冲突,以本文件作为 **Agent 使用口径**。
- 若将来 ANC 长到需要独立成体系,再开新 issue 决定载体;不在没有需求时先建。
