# 权限与鉴权:完整指导

> Phase 3 用,与 interface-data-check.md 配合。目标:把「能不能访问、靠什么访问、凭证怎么管」变成可落代码的清单,而不是口头假设。
>
> **落地原则:网关级约束(鉴权方式/校验规则/目录白名单/重试限流)按实际接口、权限、数据情况落地,不套模板——实际情况是什么就落什么;拿不准的权限边界,提问由人定(#12-30)。**
>
> **D1/D2 追加**:账号必须实名/服务化,禁止共享与借用;生产写默认不允许;三权分离、审批记录、审计日志、模型/API 白名单见 `enterprise-delivery.md` §4-6。

## 一、鉴权方式清单(每条数据流都要标)

| 鉴权方式 | 通道档位 | 切片影响 | 凭证形态 |
|---|---|---|---|
| API token / key / secret | ✅ 直连 | 可全自动 | 环境变量,不进仓库 |
| OAuth / SSO 登录态 | ✅ 直连 | 可自动化,注意过期 | 刷新 token,轮换机制 |
| 证书 / IP 白名单 | ✅ 直连 | 需在客户网络内跑 | 证书文件,不进仓库 |
| 服务账号 + JIT/临时提权 | ✅ 直连(需审批) | 可自动化,最小权限 | 客户 secret manager;有 owner/到期日 |
| 账号密码(共享账号) | ❌ 禁止(D1/D2) | 无法归责、无法审计 | 不落盘、不使用;改用服务账号 |
| 借用个人账号 | ❌ 禁止(D1/D2) | 违反实名/审计/风控 | 停止,申请正式权限 |
| 人工审批后开放 | ⚠️ 人肉桥 | 审批拖延=时间卡点 | 审批记录留档 |
| 无任何通道 | ❌ 不通 | 切片没输入 | 降级:只读/脱敏样本/公开数据 |

## 二、权限矩阵模板(Phase 3 产出,写进计划书 §6 权限列与 §11 控制面)

```
| 资源 | 操作(读/写/执行) | 凭证 | 持有人 | 谁能批 | 有效期 | 最小范围 |
|---|---|---|---|---|---|---|
| 客户后台导出 | 读 | 服务账号(客户所有) | 数据平台组 | 数据 owner + 安全 | 90 天 | 只读,仅导出接口,不碰设置 |
```

## 三、最小权限原则

1. 只拿切片需要的**最小范围**:能读就不写,能拿单列就不拿全表,能拿脱敏样本就不拿生产全量。
2. **生产写默认不允许**;确需写 → 单列操作、白名单、幂等、审批、审计、回滚,不能批量裸写。
3. 要不到全量 → 问:只读行不行?脱敏样本行不行?抽样 1000 行行不行?
4. 要不到任何访问 → 该数据流标 ❌,按卡点预案降级(换数据源 / 交付 F2)。
5. 权限有到期日;项目结束/换人立即回收,不用「反正以后还要用」保留。

## 四、凭证处理规则(必须落代码,靠 prompt 记不住)

1. **不进仓库**:密钥/证书/token 一律环境变量或独立密钥文件,`.gitignore` 兜底。
2. **不进文档**:计划书、采矿笔记、日志里只写「有 token,存于 X」,不写凭证本身。
3. **不进日志**:脚本日志脱敏,不 print 凭证;报错信息不含 key。
4. **轮换与过期**:token 过期是卡点类型之一,预案=自动刷新或人工换新;过期时间写进权限矩阵。
5. **沙盒运行**:客户数据相关脚本只在客户批准的沙盒/测试环境/跳板机跑;本机只允许合成数据或客户书面批准的脱敏样本。生产数据不得落个人设备/个人云。
6. **脱敏样本**:经客户批准、不可逆、评估再识别风险后才可入库;未批准不得进仓库/案例/演示。脱敏 ≠ 匿名。
7. **密钥管理**:用客户批准的 secret manager/环境变量注入;不得把密钥写进代码、Prompt、Notebook、日志、截图、工单。
8. **凭证隔离**:测试/生产不同凭证;模型凭证与数据凭证分开;不同客户不共用。

## 五、鉴权类卡点与预案

| 卡点 | 样子 | 预案 |
|---|---|---|
| 无鉴权通道 | 数据拿不到 | ❌ 标不通,换数据源或 F2 |
| 审批拖延 | 权限申请一周没批 | 时间红线(G 类#4)记录,并行用脱敏样本先开发 |
| token 过期 | 脚本跑到一半 401 | 自动重试 1 次 → 降人工导出;刷新逻辑进代码 |
| 借用账号风控 | 客户账号触发风控 | 停用借用;申请服务账号;改人工导出,脚本只在批准环境处理 |
| 凭证泄露 | 仓库里发现 key | 凭证红线:立即移出 + 轮换 + 检查日志 |

## 六、企业账号、三权与审计(D1/D2)

1. **实名账号 + MFA**;服务账号归属客户、有 owner、有到期日。
2. **三权分离**:开发者不能自批、自发、自审;生产写至少四眼。
3. **最小权限 + JIT**:临时提权限时、留痕、用完回收;break-glass 仅紧急,事后复核。
4. **审计日志**:谁、何时、对什么数据、做了什么、结果如何;日志脱敏、不可篡改、按客户保留期。
5. **权限复核**:上线前、项目结束、人员变更时复核;离职/换人回收。
6. **客户角色缺失** → 记「待客户确认」:D1 停在 G4/G6a,D2 再加 G6b;不替客户补角色。

## 七、模型/API 白名单(D1/D2)

1. 只使用客户批准的模型/端点/区域;版本锁定;记录供应商数据保留/训练条款。
2. 客户数据进模型前确认:是否允许、是否脱敏、是否跨境、是否留存/训练。
3. 模型凭证集中管理;Agent 不直接持有高权限模型 key。
4. 外部模型不可用 → 本地模型/规则/人工降级;不得静默失败或偷偷切到未批准端点。
5. Prompt/输出日志遵守数据分级;不把生产数据写进调试日志。

## 八、合规红线(过 G3/G4 才许用)

1. 数据出不出客户边界,是**硬约束**:D/C 只能提出业务必要性,批准必须来自客户授权角色(I/S/法务/数据 owner),按客户制度留书面记录;FDE 不自定,也不把「开发者说可以」当批准。
2. 涉及个人信息/敏感数据(客户名单、结算金额)→ 停,先问 D 业务口径,并由 S/法务确认合规口径,再定脱敏/最小化方案。
3. 鉴权方案(服务账号/申请 token/只读/JIT)写入三区表:硬约束(客户规定)/ 决策(双方商定),G4 逐条签字;共享/借用账号在 D1/D2 不是选项。
4. 跨境/外发第三方模型(十类 #1 后半句)未确认前,数据一律不出客户环境。
5. D2 准入按 `enterprise-delivery.md` §10;任一 L3/L4 数据或生产写操作未确认 → 不发布。
