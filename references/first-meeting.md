# 一号位沟通:从会前假设,到 POC 一页纸

> Phase 7 用。**来源**:HA7CH 一线企业沟通经验 + 《麦肯锡方法》可用部分(转述)。
> 一句话:**聊得愉快不是推进;真正的推进必须出现负责人、数据、范围、指标和时间。**

## 一、先换身份:你是价值伙伴,不是来求人的

不是去求老板做 AI 改造,而是带着一种他当前缺少的能力,和他一起判断企业里有没有值得做的事。

- 一号位拥有:场景、数据、组织资源、决策权。
- 你拥有:AI 能力、产品化能力、外部案例、落地方法。
- 双方各握着对方需要的东西。

**换位思考 ≠ 迎合**。站在一号位的收益、风险、时机和机会成本上想:为什么现在做?能省什么钱、增加什么产出?不做会错过什么?做错成本可控吗?怎样用最小动作判断值不值得继续?

**专业自信不是"什么都能做"**,而是敢清楚表达:这部分确定、这部分待验证、这部分不能做、这个项目不适合合作。

## 二、没见到一号位,先别做重方案

"一号位"不是固定 title,而是**能决定目标流程、数据权限、预算和组织协作的人**。当前联系人决定不了 → 先问能否直接与一号位沟通。

**没有一号位参与的跨流程改造,往往只能停在"大家觉得有意思"。** 此时不要继续免费写完整方案或做重 POC。

## 三、会前功课:不是成为行业专家,而是形成产品假设

会前稍微看懂企业怎么赚钱、业务怎么流转:卖什么/客户是谁/钱从哪来、主要成本与风险在哪、获客→成交→交付→回款怎么流转、哪些岗位处理大量信息、哪些环节高频重复易错延误返工。

再看同行、同类企业解决方案、垂类 Agent 与相似案例:哪些问题已经有人做、解决的是哪个环节。

**每个机会必须压成产品句:**
> 在【业务环节】中,【具体角色】处理【输入】,当前因为【问题】造成【损失】,可以用【产品形态】改善,并用【指标】验证。

"给企业做一个 Agent"不是产品定义。

**机会分三档**:
1. **确定能做**:已有事实或案例,见面优先讲;
2. **值得验证**:原理可行,需要真实数据或现场;
3. **暂时不做**:数据、使用者、收益或实现路径不成立。

## 四、30 秒表达(只讲四件事)

1. 我们做什么;
2. 做过什么相似结果;
3. 这家企业确定能先做什么;
4. 用什么动作判断是否继续。

**先讲业务结论,技术细节留给追问。**

## 五、在桌上:建立信任与边界

- **首次沟通少问,按意愿逐步深入**:老板还没确认你的价值时,一次抛太多问题会变成审讯。
- **用业务语言匹配对方的认知阶段**:对方讲成本你就讲成本,别一上来讲模型和架构。
- **技术风险要转成"边界 + 验证动作"**:不说"没问题",说"这部分确定/这部分要拿真实数据验证/这部分不能做"。
- **不诋毁竞品**:用事实比较适配度,不说"他们不行"。
- **pushback 五步**:① 承认对方希望达到的目标 → ② 给出你的专业判断 → ③ 说明约束和影响 → ④ 提供可选择方案 → ⑤ **锁定下一决定**。
- 保持平等,不低三下四,也不教育客户。**不是所有客户都必须吃下来**;停止纠缠不适配的合作也是专业。

## 六、判强弱意愿(决定投入多少)

**弱信号**:"有意思""回头聊""发点资料看看"。
→ 不发长问卷、不免费做完整方案、不启动重 POC;保持联系,用真实案例与进展持续攒可信度。

**强信号**:愿意见业务一号位、提供脱敏样本、指定内部负责人、共同定义指标和时间、讨论预算或正式验证。
→ 出现强信号后,再进入结构化诊断。

## 七、主裁与盟友:节奏由主裁定,议程扩展靠盟友

现场往往不是一个人:

- **主裁**决定推进节奏与场景取舍——他先说做哪个,就先做哪个。
- **盟友**(可能仍认可你原来的方案)负责在后续把新议程带回来。

**两条硬纪律:**

1. **谁再提被喊停的方案,谁出局。** 客户当场喊停你准备已久的方案时:不为原方案辩护、不追问「为什么」;当场把新场景的输入 / 输出 / 边界问清;**对该负责人以后不再提原方案**。
2. **被喊停的方案封存不销毁。** 写清「由谁、在什么条件下重启」;回头路径通常只有一条——**先用新场景赢下第一期、建立信任,再经由盟友重新提起**。

> 这条来自真实场景:需求会上财务负责人(现场实际主裁)当场喊停已准备两周的报销预审(「链条太长」),转向网银只读自动化。团队据此立规:对这个人绝不再提报销;原方案产出全部封存为沉没资产。

## 八、从全流程愿望切成可判断试点

**试点梯度**:数据诊断 → 离线 Demo → 单环节 POC → 小范围真实使用 → 指标达标后再扩展。

**内部培训不是默认第一步**。先完成一个具体优化;企业准备推广新工作方式时,再用培训帮员工理解:AI 优先接管重复操作,人转向判断、责任、创造和沟通。

## 九、POC 一页纸(必含九项)

1. 业务环节和使用者
2. 输入、输出与**明确不包含的范围**
3. 数据与权限
4. **双方负责人**
5. **时间边界**
6. **成功指标**
7. **不成功时何时停止**
8. 达标后的下一阶段
9. 价值口径(不只裁员:单位时间产出、错误返工、响应速度、服务容量、员工能否承担更高价值工作)

> 只需数据、指标、负责人、时间**缺任一**,就还没真正推进。

**关于数据与权限**:见到一号位后,不需要问"员工愿不愿意配合"——跨流程改造需要一号位正式授权,员工配合是执行要求。**也不要索要员工私人密码**;通过现场观察、屏幕演示、脱敏导出、受控账号、只读权限或测试环境理解工作即可。

## 十、会后复盘(10 分钟内)

- 哪句话建立信任?
- 哪句话造成犹豫?
- 是否问得过多?
- 是否形成下一步?
- **下次只改一个动作。**

原始录音和客户敏感信息**不要写进学习存档**。
