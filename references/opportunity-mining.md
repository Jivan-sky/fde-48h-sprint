# 文档采矿:细节点 → 机会点(核心增量)

> 本文件的用法:读需求文档时,带着下面五类线索去挖。cron-adapt 读文档是为了理解已知能力;你读文档是为了**挖出对方没说的东西**——被掩盖的痛点、重复的手工、被骂的场景、数据的埋点、真需求的影子。

## 五类采矿线索(读文档时逐条扫)

### 1. 被掩盖的痛点(写的是 A,痛的是 B)

文档说「我们要个平台」,读出来可能是「不想天天手工整理」。
- 线索词:平台、系统、统一、整合、打通、标准化、提效、赋能
- 反读:这些词背后的**具体动作**是什么?谁在做?为什么烦?

### 2. 重复手工动作(频率最高的动作 = 切片候选)

文档里出现频率最高的动作,就是机会点。
- 线索词:每天/每周/每月、手工、整理、汇总、录入、复制粘贴、导出、截图、发群里
- 问:这个动作一次几分钟?几个人做?错一次成本多少?

### 3. 数据埋点(文档提过的报表/导出/字段 = 切片输入线索)

文档里提过的任何数据实体,就是切片吃什么。
- 线索词:报表、导出、后台、数据、字段、Excel、表格、看板、明细
- 问:这些数据在哪?谁有权限?能导出成什么格式?——**这就是薄切片的输入**。

### 4. 被骂场景(返工/出错/纠纷 = 价值锚点)

文档里出现的返工/出错/纠纷描述,就是痛点锚点。
- 线索词:出错、返工、被骂、投诉、纠纷、对不上、漏了、背锅、加班
- 问:最近一次是哪次?谁擦的屁股?花了多久?——**这就是验证话术的锚**。

### 5. 「要是能…就好了」句(真需求的影子)

文档或对话里最接近真需求的一句话。
- 线索词:要是能、如果能、最好能、希望、要是自动、要是直接
- 记录:原话 + 对着哪个动作说的——**这就是机会点的直接来源**。

## 产出:三张清单(带证据,不裸点)

采矿完成,产三张清单。**每个机会点必须带证据**(文档哪段/哪句话),无证据标「待确认」。

```
## 1 表面需求清单(对方说的)
- 需求 A:<逐条,带出处(文档 §x / 第 x 段)>
- 需求 B:...

## 2 细节点清单(挑出的关键细节)
- 谁在用:<姓名/角色,带出处>
- 什么动作:<具体动作,带出处>
- 什么数据:<单据/报表/字段,带出处>
- 什么频率:<每天/每周,带出处>
- 什么事故:<返工/出错/被骂,带出处>

## 3 机会点候选(1-3 个,每个带证据)
- 机会点 1:<痛点 + 证据(文档哪段/哪句话)>
- 机会点 2:<痛点 + 证据>
- 待确认点:<线索但证据不足,标「待确认」>
```

## 诚实条款生效点

- 文档没写的字段 → 标「文档未提及,待确认」,不脑补。
- 文档写了但没证据支撑的 → 标「无证据,待确认」。
- 所有机会点候选,只有进 Phase 2 经用户确认后,才在计划书里写成「机会点」。

## 采矿笔记的形态(进 Phase 2 前给用户看)

```
📋 文档采矿笔记
表面需求:3 条(全部带出处)
细节点:5 条(谁在用/动作/数据/频率/事故)
机会点候选:2 个(各带证据)
证据最弱:谁拍板 vs 谁在用(文档没写)——Phase 2 必问
```
