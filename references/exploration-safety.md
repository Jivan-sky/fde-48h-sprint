# 探索安全:只理解系统,不改变系统

> Phase 4 / G3 用;也用于接收 `web-capability-sniffer` 的探查结果。
> 一句话:**探索阶段的授权只扩大「可记录范围」,不扩大「可执行范围」。**

## 为什么单独有这一层

Demo 开发可以「先点一下试试」,因为坏了重来即可。企业系统不是:

- 一次误触可能删掉一张表、停用一个账号、发出一批通知、改掉一套权限;
- 恢复成本可能远高于开发成本,而且会留下审计事件;
- 「我只是想看看这个按钮干什么」不构成操作授权;
- 客户口头说「你随便看」,不等于授权你改变生产状态。

所以探索阶段的目标只有一个:**把系统读懂,把证据留下,把风险标出来**。写操作是另一个阶段、另一套授权、另一套控制。

## 探索不是安全测试

本 skill 只做业务理解与证据整理，不做渗透测试、漏洞扫描或越权验证。以下动作即使出于“确认风险”的目的，也一律按 C 类处理：

- 端口扫描、目录/路由/账号枚举、字典爆破；
- SQL 注入、XSS、SSRF、命令注入、文件包含等主动探测；
- IDOR/越权验证：改对象 ID、租户 ID、角色参数去“看看能不能访问”；
- 参数篡改、绕过前端校验、修改 DOM/JS、关闭客户端保护；
- 使用扫描器、爬虫或 fuzz 工具对目标批量发请求。

**判断逻辑**：探索阶段只需要知道“入口存在、方法/路径线索、权限要求、副作用与回滚预判”；不需要证明“这个漏洞能不能利用”。证明漏洞是安全测试，必须另立授权、另立环境、另立工具链。

## 三级动作策略

| 级别 | 定义 | 允许做什么 | 例子 |
|---|---|---|---|
| **A 只读观察** | 不改变服务器、账号、资金、外部可见状态，且副作用可预测 | 打开、滚动、展开、切换标签、翻页、排序、只读详情、合成条件查询、截图、记录网络轮廓 | 打开客户列表、按合成关键词查询、翻页、看详情 |
| **B 入口识别** | 有副作用或可能改变状态,但需要知道它存在 | 只记录入口、按钮文案、路由、请求方法/路径、参数名、入口已可见的确认文案;**不点击、不提交、不打开高危确认弹窗、不执行** | 新增、编辑、保存、提交、发布、删除、导出、上传、审批、支付、改权限 |
| **C 绝对禁止** | 高风险、不可逆、批量或无法判断副作用 | **不尝试、不探测、不重放、不生成可执行脚本** | DDL/DML、批量删除、清空/重置/初始化、权限变更、资金、对外发送、生产配置修改、主动扫描/越权探测 |

**判断顺序**:先按业务副作用判断,再按 HTTP 方法判断。只读查询即使是 POST 也可以观察;产生状态变化的 GET 也必须按 B/C 处理。

**“可以观察”的准确含义**:页面在正常 A 类操作中自己发出的请求,可以记录其方法、脱敏路径、参数名和响应轮廓;不得把请求复制出来,用 curl/脚本/fetch/控制台重放。方法本身不构成只读证明,业务副作用才是判据。

**A 类也有前提**:打开/刷新/展开/查询前,必须先判断是否会触发自动保存、自动提交、异步任务、导出任务、消息发送或业务状态变化。无法判断时不做,按 C 处理。正常访问/操作审计留痕是预期结果,应记录,不按副作用处理。

## 二十条硬规则

1. **探索阶段写操作执行数必须为 0。** 包括 UI 点击、接口调用、SQL、脚本、CLI、浏览器控制台。
2. **授权不改变执行边界。** 客户/用户授权只影响「你能记录到什么深度」,不影响「你能执行什么」。
3. **任何「先试试看」的写操作 = 违规。** 想验证写接口,移交受控变更流程,不在探索里做。
4. **副作用不确定 = 按 C 处理。** 不要用「应该不会写」赌。
5. **禁止 DDL/DML**:`CREATE`、`ALTER`、`DROP`、`TRUNCATE`、`DELETE`、`UPDATE`、`INSERT`、`MERGE`、`REPLACE`、批量导入。
6. **禁止权限/配置变更**:授权、角色、黑名单、白名单、密码、密钥、开关、版本、发布状态、工作流配置。
7. **禁止对外副作用**:发消息、发邮件、发短信、通知、公告、审批、支付、退款、转账、下单、发货。
8. **禁止批量与初始化**:批量分配、批量清洗、批量归档、清空、重置、初始化、覆盖导入。
9. **禁止重放任何请求**:不要把浏览器里的请求复制出来用 curl/脚本/fetch 重放,也不要重放 `GET`/`HEAD`/`OPTIONS` 或所谓「只读 POST」。探索只观察页面自身产生的请求;确需补证时,移交客户批准的只读验证流程,不在本 skill 内执行。
10. **禁止点击最终确认**:保存/提交/发布/删除/支付/审批的最终按钮一律不点;出现确认弹窗立即停止,按 Esc/关闭,记录文案。
11. **禁止高权限账号**:优先只读账号、最小权限账号、测试租户;禁止管理员、共享账号、生产负责人账号。**生产环境只接受真实只读账号或客户正式提供的只读角色;管理员/共享/生产负责人账号即使有书面例外,也不用于生产探查,转人工只读操作或另立安全测试授权。**
12. **所有动作留审计**:时间、URL、动作、选择器、结果、请求方法/路径、副作用判断;失败也记录。
13. **页面自动业务副作用也算写操作**:如果打开/刷新/展开页面后,服务端自动创建、修改业务对象、发送外部消息、扣费或启动不可撤销的异步任务,立即停止后续加载,保留证据并按事故响应;不得用「页面自己发的」免责。**正常的访问/操作审计日志是只读访问的预期留痕,必须记录,不算业务写操作;只有日志记录的业务状态变化、外部通知或异步任务才按副作用处理。**
14. **不打开高危确认弹窗**:删除/清空/重置/批量/权限/资金/对外发送的确认弹窗,一律不打开;即使客户/用户单独授权,也不在本探索流程内打开。只记录入口已经可见的文案;确需弹窗文案时,由客户提供截图/文档,或移交独立安全测试流程。
15. **禁止主动安全测试**:不做端口扫描、目录/路由/账号枚举、字典爆破、注入探测、IDOR/越权验证、参数篡改、fuzz 或任何漏洞利用尝试。
16. **禁止修改客户端**:不改 DOM/JS、不关闭前端校验、不注入脚本、不自动接受确认弹窗、不自动提交表单。
17. **登录不等于写许可**:在客户分配的授权账号内完成登录/会话建立是允许的,但只限登录本身;不得创建账号、改密码、改角色、改权限、共享账号或借用个人账号。不得记录口令、验证码或 MFA 值;登录流程若要求改密、绑定、授权或接受条款,立即停止并移交客户。
18. **禁止原始证据外带**:不导出 HAR、不保存完整请求/响应、不保存含个人信息的截图;网络证据只在内存中提取脱敏轮廓。
19. **控制资源消耗**:限制并发、频率和总时长;查询/分析/生成任务可能消耗大量资源时,先停并确认,不把生产系统当压测环境。
20. **批量导出按 C 处理**:全量/批量导出、下载业务数据、上传文件、导入/同步/迁移,只识别入口;单条只读查询也必须有合成/脱敏条件。

**审计留痕口径**:访问、刷新、查询和登录在客户系统留下审计/访问日志,是受控环境的正常结果,应记录为“预期留痕”;这不等于获得了写入许可。判断是否发生业务写入,看业务对象、外部副作用、资金、异步任务或配置状态是否改变,不看是否新增了一条访问日志。

**逐动作审计**:探索期间每个打开/刷新/查询/展开/翻页/截图/入口识别都要记一行:时间、脱敏 URL、动作、A/B/C 级别、执行状态、结果、请求来源、副作用判断、证据 ID。报告必须附这张表;只有汇总数字“写操作=0”而没有逐动作记录,视为不可验收。

**测试环境也不是写许可**:本 skill 在任何环境(包括测试/沙盒)都不执行写操作。需要在测试环境写入时,另立 FDE 受控写入流程(G6a + `write-gate-record.md`),并确认数据可重置、影响范围、清理/回滚和证据位置。

| 重置/初始化 | 重置、初始化、恢复默认、覆盖、回滚、reset、init、restore、overwrite、rollback |
| 发布/生效 | 发布、上线、启用、停用、提交、保存、生效、publish、deploy、enable、disable、submit、save |
| 权限/账号 | 授权、分配、转移、改密、绑定、解绑、角色、权限、grant、revoke、assign、role、permission |
| 对外/资金 | 发送、通知、公告、审批、通过、驳回、支付、退款、转账、充值、下单、send、notify、approve、pay、refund |
| 批量/导入 | 批量、全选、导入、同步、迁移、batch、bulk、import、sync、migrate |
| 导出/下载 | 导出、下载、另存、打印、export、download、saveas、print |
| 异步/计算 | 生成、分析、计算、刷新缓存、重建索引、跑批、generate、analyze、rebuild、refresh |

## 可追溯 / 可回滚预判(每个 B/C 能力都要填)

探索阶段不写,但必须判断「如果将来要写,这个系统能不能被控制」。对每个 B/C 能力记录:

| 问题 | 要拿到的证据 | 拿不到时 |
|---|---|---|
| 有没有审计日志? | 日志字段:谁/何时/什么对象/前后值/结果 | 标「未知」,默认不可写 |
| 能不能撤销? | 撤销入口、软删除、版本历史、回收站、撤销窗口 | 标「未知」,默认不可写 |
| 有没有快照/备份? | 备份对象、频率、保留期、恢复入口 | 标「未知」,默认不可写 |
| 恢复演练过吗? | 最近一次恢复演练记录、RTO/RPO | 标「未演练」,不得称可回滚 |
| 外部副作用可逆吗? | 消息/支付/审批/通知是否已发出、能否撤回 | 不可逆 → 只读或人工执行 |
| 权限能收回吗? | 授权模型、回收路径、生效延迟 | 标「未知」,默认不可写 |

**结论只能落在五档**:

- `只读安全`:无副作用;
- `可写但需快照`:有快照/备份且能恢复;
- `可写但需审批`:有审计/撤销,但需人工放行;
- `不可写`:不可逆、无审计、无回滚;
- `未知`:证据不足,按不可写处理。

`未知风险` 不是“暂时当只读”的理由。证据补足前按写风险处理:不标 `已验证 API`、不进入 CLI 草案/待验证、不标 `可重放`、不标 `只读安全`,且必须先补一行可追溯/可回滚评估。

**未知风险不得进入写入设计**:`未知` 或 `不可写` 的能力只能在 M0/M1 做只读、人工桥或禁用占位;要设计写路径,必须先把副作用、审计、撤销/快照、外部影响补成有证据的 `可写但需快照` 或 `可写但需审批`。补不齐就停止,不得用“先写一点看看”补证。

## 与 FDE 的交接

`web-capability-sniffer` 的输出不是「可以开写的接口清单」,而是「判断上下文」:

- 系统地图、页面/菜单/路由;
- 接口清单、鉴权方式、权限矩阵;
- 数据模型/schema、关键字段与枚举、业务状态机;
- 只读数据样例(脱敏);
- 每个能力的风险级别与副作用;
- 可追溯/可回滚预判;
- 未知项、证据等级、置信度。

**不输出**:可直接执行的删除脚本、可直接调用的写接口、绕过审批的账号/凭证、未经验证的生产操作步骤。

FDE 在 Phase 4/G3 接收这些材料,决定:

1. 这个切片是否必须写?能不能只读?
2. 如果必须写,写什么对象、影响范围多大?
3. 有没有快照/回滚/审计?没有 → 停,补控制或改只读方案;
4. 是否需要 D1 沙盒先演练?是否需要客户变更单?
5. 写入方案移交 `write-safety.md`,不在探索阶段执行。

## 事故响应(万一还是发生了)

1. **立即停手**:停止当前路径,不再点、不再调、不再重试。
2. **保留现场**:截图、记录时间、URL、动作、请求、返回;不要覆盖日志。
3. **通知 owner**:客户业务/IT/DBA/安全,按客户 incident 流程。
4. **先隔离,再恢复**:不要用「再写一次」掩盖;恢复前确认备份/快照可用。
5. **在影子环境验证恢复**:能恢复到影子环境并核对数据,再考虑生产恢复。
6. **记录与复盘**:根因、影响范围、恢复步骤、证据、改进项;更新本 skill 的 deny-list 和门禁。

> 误删表的教训:真正昂贵的不是删除动作,而是「删完继续点、继续试、继续补」导致现场被覆盖。第一动作永远是停手和保留证据。

## 桌面演练(未在真实客户环境执行时,只能标「未演练」)

用下面五个场景训练判断,不要求真的点:

| # | 场景 | 正确动作 | 错误动作 | 预期记录 |
|---|---|---|---|---|
| 1 | 列表页工具栏出现「删除」 | 只记录按钮文案/入口;不点;不打开确认弹窗 | 点一下看弹窗长什么样 | `写操作未执行`;风险=生产写入;结论=不可写/未知 |
| 2 | 搜索框输入条件后页面发 `POST /search` | 先判断是否只读;只在页面正常查询中观察请求轮廓 | 复制 curl 重放、改参数探测 | `只读安全`;记录方法/路径/参数名;写操作=0 |
| 3 | 打开报表页自动生成异步导出任务 | 立即停止后续加载,保留证据,按事故响应 | 等它跑完、再点一次 | 记录自动副作用;通知 owner;写操作=0(但已发生副作用需上报) |
| 4 | 看到用户 ID,想改成别人的 ID 验证越权 | 不做;标记为「需安全测试授权」并移交 | 改 URL/请求参数试一下 | `未执行`;风险=未知;不得记录他人数据 |
| 5 | 页面弹出「确认删除」 | 按 Esc/关闭,记录文案 | 点「取消/确定」都算交互;不点 | `已识别未执行`;不打开高危弹窗 |

## 自检

- 探索阶段写操作执行数 = 0?
- B/C 动作是否全部只识别、未执行?
- 每个 B/C 能力是否填了可追溯/可回滚预判?
- 未知项是否按「不可写」处理?
- 有没有记录凭据值、完整请求/响应、行级业务数据?
- 有没有生成可直接执行的写脚本?
- 有没有重放过任何请求,或把「页面自动发的」当免责理由?
- 出现确认弹窗/删除按钮/批量操作时,是否立即停止?
- 是否把正常访问审计误判成事故,或反过来把业务写入藏在“审计日志”里?
- 事故是否有停止、通知、证据、恢复、复盘?
