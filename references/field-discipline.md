# 现场纪律:本土案例里最容易踩的那些坑

> Phase 8/9 用。**来源**:HA7CH / Lawted 现场素材(制造业试点、金融场景转向、公开访谈等,已脱敏)+ 本库 ANC 落地案例库(转述)。
> 每条都对应一个踩过的坑。**没踩过也当踩过。**

## 一、证据分级(所有结论先标级)

| 级 | 含义 | 用法 |
|---|---|---|
| **L1 已闭合** | 有代码/记录可查 | 可作结论 |
| **L2 现场素材** | 访谈/复盘;项目可能进行中或未签约 | 可作判断依据,须标"未验收" |
| **L3 公开口播** | 公开说法,未与合同/回款闭合 | **只作线索,不作结论** |

**纪律**:客户名/金额/合同/内部人物不写进对外材料;项目进行中就写"进行中",不写"已达成"。

## 二、三条线分开(对客户/对内部)

- **合同线**:合同写明的交付物按**最小口径**逐项交付,只有刻意做厚的那一项例外。
- **糖果线**:合同之外、汇报时才亮出来的加分项。**平时不承诺,汇报才亮。**
- **沉淀线**:方法、脚本、bot 配置等内部资产,**对外不提**。

**最常见的错误**:把糖果线当合同线承诺出去;或把沉淀线拿去跟客户邀功。三条线分开,才有"对内标准化、对外 100 分定制"的空间。

## 三、三类基线分开算(诊断/一阶段)

| 基线 | 回答的问题 | 责任人 |
|---|---|---|
| 项目关键路径基线 | 哪些任务、依赖、阻塞真正决定里程碑 | 项目经理整合,各部门确认本部门节点 |
| 部门工作基线 | 人力投在哪、产出结构、瓶颈 | 部门负责人 |
| 个人任务基线 | 一项任务过去怎么做、投入多少、AI 可能怎么参与 | 员工填真实样本,负责人校准 |

**纪律**:
- **劳动时间与等待历时分开记**。任务省时只有在消除关键路径真实阻塞后,才能推断项目周期改善。
- **量表折算出来的小时数必须标"量表折算",不能冒充计时实测**;区间不压成精确值。
- **没有测量覆盖率和专业验收证据,不报告个人/部门/公司整体提效**;报告时任务节省率、覆盖率、标准工时释放率、关键路径影响**同时给**。
- **不做个人排名**;基线服务于试点选择与前后对比,不用于绩效。

## 四、信息只搬运一次

不要先造一个新工具。把**客户已有的、每周必发的东西**(如周报)定成样板工作流:固定时间发、固定时间收、收完自动同步。

标准一句话:**员工写一次,管理层就该看到任务级进度,不需要第二次填报。**

## 五、调研做成"帮你整理",不是"请你回答"

客户做过问卷型调研、员工敷衍有前科时:
1. 做成"帮你把这周工作整理成周报"的形态,**一次只问一个问题**;"这周没新增"也算有效事实。
2. 老板站台,两周内覆盖全员,催收进日历。
3. 按部门和岗位路由:**通用 / 部门侧重(只问增量与阻塞,不重复盘问"你平时做什么")/ 给已用 Coding Agent 的岗位走 A2A**(发一段提示词,员工自己的 agent 扫本机近期工作,整理成摘要以本人身份发回)。
4. 报告只记工作事实,**不生成绩效、排名、忙闲或能力评价**;员工侧收口只有一段文字小结和致谢,**不发报告**。

## 六、敏感线(通用化写法)

- **技术负责人内向、重技术** → 由一名 FDE 单线维护,不硬压,**不越过他直接找他的下属**。
- **采购/财务/法务** → 不采集聊天记录与录音,只用流程文件与客户已给的模板。
- **客户口径若是"加项目不加人"** → 所有价值表述跟着这个口径走,**别用"提效=裁员"的叙事**。
- **不碰客户的核心设计/工艺** → AI 只落在文档、资料查询、跨部门协同和重复操作上。

## 七、安全边界是信任的起点

对财务/法务这类场景,**先说不做什么**往往比先说能做什么更有效。写进方案的三条典型边界:
1. 只做**只读**自动化,不碰付款与转账接口;
2. 敏感凭据加密落在客户局域网内,不走任何外部 SaaS;
3. 所有操作**可审计**。

## 八、客户给模板,就回填格子,不反向发长问卷

- 签约前发 34 条尽调清单,客户看到的是"还没签就要我交这么多东西" → 改成**客户给格子,我们只回填格子**。
- 客户给了报价模板:**按模板拆项**(软件许可/实施人天/硬件/维保 × 年订阅),**每个数字逐格核对**;明细列与合计栏不一致时,**在报价里显式写明按哪个算**(例:明细写 12 个查询盾、合计写 20 → 必须锁死"12")。

## 九、人机分歧回原件

现场 Demo 里 AI 与人工记录不一致时:不要求现场相信模型,而是**用结果里的来源指针重新打开原件、定位对应位置**核对。
- 输出与原件位置同时返回;
- 保留原始输入、模型输出和人工修改;
- 分歧时**不让模型自证**,直接回到证据;
- **失败与修改同样进入记录**,不展示成功路径。

## 十、入口成本账

面对纸单,两种默认都错:默认"保留习惯就上 OCR",或默认"让所有人改用新工具"。

**先数真正操作的是谁、几个人**:
- 若是数十名稳定角色 → 小规模培训后在既有 IM 里提交,可能比长期维护 OCR 更便宜;
- 若入口覆盖几百上千人 → 注册、培训、答疑、持续支持成本迅速放大,此时保留原入口、加 OCR 或导入层更合理。

比较的是:**培训推广 + 持续支持** vs **适配层建设 + 维护 + 错误复核**的总成本。人数不是硬阈值,还要看角色稳定性、使用频率、数字工具熟悉度、错误代价。

## 十一、Context 的形状决定架构

- markdown / 小文件 / 低数据量 → 可先轻量方案,由个人 Agent 直接读;
- 大量图片、PDF、多 GB 项目资料 → 文件和执行要靠近企业(托管或本地);
- 单个业务对象能被直接文件、结构化摘要和确定性检索覆盖 → **不默认预建 RAG**;
- 企业 IM 只解决入口,**不能替代 Context 真相源、Skills、权限、执行与反馈环境**。

**每个架构选择都要挂一条现场约束**,别背模式。

## 十二、验收与团队协作

- **部门认可 ≠ 正式验收**:录音 + IM 留痕可作内部检查点,但**不能替代约定签字**;签字未取得前标"待正式验收"。
- **多 FDE 多 Agent 协作只维护三份文件**:
  1. **任务看板**:ID / 目标 / 主责 / 输入 / 允许修改的文件 / 产出 / 确认人 / 状态
  2. **决策记录**:只记影响多个任务或目录的决定
  3. **交接模板**:完成了什么 / 改了哪些文件 / 依据 / 验证 / 剩余问题
- **三条纪律**:一个文件同一时间只有一个主责;原始逐字稿只追加勘误不改写;**仓库里的"已完成" ≠ 项目验收**。
