# 执行对照清单：每 Phase / 每 Gate 的任务明细 · 处理方式 · 职责 · 违规后果

> 全程可读（按需取本 Phase 小节）。职责记号：**A**=Agent（你）/ **D**=开发者 / **C**=客户业务拍板人 / **F**=一线 / **I**=客户 IT / **S**=安全·合规·QA / **R**=发布人 / **O**=运行 owner / **Aud**=审计。违规后果 = 命中即停修或回退对应门。
>
> **D1/D2 追加**：每阶段都要带控制面任务；D1 控制角色缺失 = 停在 G4/G6a，D2 再加 G6b。D0 可跳过控制面细节，但不得把 D0 证据用于 D1/D2。
>
> **写入判定权威**：本文件末尾的 25 项写入闸门卡是唯一判定清单；`write-gate-record.md` 是逐次留痕模板；`write-safety.md` 是方法与执行顺序。不得只引用其中一套，也不得用“做了快照”替代逐对象 before-image 和补偿映射。

## Phase 0 — 前置：路线、轨道、模式、岗位与控制角色（G1）

| 项 | 内容 |
|---|---|
| 任务明细 | ①选路线 A/B；②选轨道 S/P；③定 D0/D1/D2；④填环境/工具/模型能力清单；⑤定输入形态（文档/口头/代码/流程描述）；⑥岗位运转判断；⑦问两题种子约束；⑧识别 accountable leader、mission DRI 与控制角色 I/S/R/O/Aud；P 轨道加 process owner/builder/coach 与角色决策权图；⑨写 planbook-state.md |
| 处理方式 | 轨道/模式不清=停；有文档→P2；只有口头→P1 后 P3；文档读不了→标待确认并问 D 要通道；不在白名单→批准替代/人工桥/F2，不安装；P 轨道先读 `delivery-tracks.md` + `org-transformation.md` |
| 职责 | A 执行；D 回答模式/两题（I/S/R/O 经 D 或直接确认） |
| 违规后果 | 跳过轨道/模式/两题=边界空白；把 P 轨道默认写成 48h 原型=轨道错位；私装工具=控制面绕过；D1 缺控制角色=不进 G4/G6a，D2 再加 G6b |
