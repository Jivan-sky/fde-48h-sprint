# fde-48h-sprint 手册:来源与用法

## 这 skill 是什么

从 `D:\FDE_HA7CH` 里两个源提取、重新拼装成的一个**计划书指导老师** skill,服务一个场景:**接收需求(文档/白皮书/纪要/口头),挑细节点,辨真伪,从文档提炼机会点,一开始就设计出「交付物核心能力 + 后续交付形式」的计划书。**

- 提取源 A:`fde-pro/skill/SKILL.md`(诊断型 → 抽出它的世界观、尺子、纪律)
- 提取源 B:`ai-native-company/light/skills/*/SKILL.md`(公司知识库 → 抽出它的对话纪律、断点续走、诚实条款)
- 架构模板 C:`D:\cron-adapt`(对话引擎版 skill → 抽出它的五阶段、上下文预算表、选择题提问、Phase 3 收敛确认)
- 拼装产物:本 skill 目录,`SKILL.md` 是正文,本文件是手册。

> 注:本文档是背景资料,了解 skill 从哪来、怎么用。**执行时按 SKILL.md 的上下文预算表走,本文件不进对话阶段。** 现场适配段(MCN/快手)是 FDE 候选人的下场场景,计划书成品样例见 `examples/mcn-planbook/`。

## 和现有 skill 的关系

- **不是 fde-pro 的替代**:fde-pro 是诊断型(判断一个人是不是 FDE、怎么改);本 skill 是计划书指导型(接需求出计划书)。诊断后给「下场」建议,本 skill 把需求变成「下场做什么」的计划书。
- **不是 gsd 系列的替代**:gsd-quick / gsd-mvp-phase 是通用工程节奏(计划、任务、验证);本 skill 是 FDE 视角的纪律层——把「反平台、经济账、价值在一线、只出薄切片」压进计划书里。两者可叠用:本 skill 管「做什么、不做什么」,gsd 管「怎么排活」。
- **和 ai-native-company 的关系**:不依赖它部署。但借了它的对话纪律。如果用户现场已经建了 vault,计划书的产物(采矿笔记、真伪结论)可以直接走 anc-ingest 入库当公司知识。

## 用法速查

1. 用户在 Claude Code 里说触发词(计划书 / 需求文档 / 接需求 / 真伪需求 / 机会点 / 帮我看这份需求…) → 本 skill 载入。
2. 先讲「对用户说」那段,对齐「不排施工计划,先判真伪、定交付物」。
3. 走 Phase 0 前置检查 → 分支:有文档采矿,只有口头提问。
4. 每个阶段结束写 `planbook-state.md`;重启读它续走。
5. 计划书生成后,Phase 5 校验:复查红线 + 负面检查,任一命中停修。
