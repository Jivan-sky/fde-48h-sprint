# fde-48h-sprint 手册:来源、用法与版本

## 这 skill 是什么

一个**计划书指导老师** skill,服务一个场景:**接收需求(文档 / 白皮书 / 纪要 / 口头),先判客户层与一号位,再文档采矿并建问题模型,辨真伪(Echo 甄别),提炼机会点,设计「薄切片交付物 + 交付形式」,出计划书,过一号位沟通与 POC 一页纸,48h 内本人端到端下场,最后沉淀与换单。**

它由四类来源拼装:

- **对话引擎纪律**(借 cron-adapt):选择题带理由、每轮 ≤3 题、收敛确认表、分阶段上下文预算、断点续走。
- **世界观与尺子**(借 fde-pro 现场真相):反平台、价值在一线、经济账自己算。
- **知识库纪律**(借 ai-native-company):诚实条款、证据分级、原始记录只追加勘误。
- **分层与诊断方法**(借 HA7CH / Lawted 公开讲义,**转述,非原文**):九宫格客户分层、问题模型五要素、一号位沟通与弱意愿、现场纪律。

> 本文件是背景资料,回答「skill 从哪来、怎么用」。**执行时按 SKILL.md 的上下文预算表走,本文件不进对话阶段。** 计划书成品样例见 `examples/mcn-planbook/`。

## 和现有 skill 的关系

- **不是 fde-pro 的替代**:fde-pro 是诊断型(判断一个人是不是 FDE、怎么改);本 skill 是计划书指导型(接需求 → 出计划书 → 推进成试点)。
- **不是 gsd 系列的替代**:gsd-quick / gsd-mvp-phase 是通用工程节奏(计划、任务、验证);本 skill 是 FDE 视角的纪律层。两者可叠用:本 skill 管「做什么、不做什么」,gsd 管「怎么排活」。
- **和知识库的关系**:不依赖它部署。但计划书的产物(采矿笔记、问题模型、真伪结论、沉淀资产)可以直接回写知识库。

## 用法速查(v3 十阶段)

1. 用户说出触发词(计划书 / 需求文档 / 接需求 / 真伪需求 / 机会点 / 客户分层 / 问题模型 / 帮我看这份需求…) → 本 skill 载入。
2. 先讲「对用户说」那段,对齐「不排施工计划,先判层、判真伪、定交付物」。
3. Phase 0 前置检查 → Phase 1 客户分层 → Phase 2 采矿 + 问题模型 → Phase 3 提问(Echo 甄别)→ Phase 4 收敛确认 → Phase 5 出计划书 → Phase 6 校验 → Phase 7 一号位沟通 & POC 一页纸 → Phase 8 下场 Sprint → Phase 9 沉淀与换单。
4. 每个阶段结束把关键信息写进 `planbook-state.md`;重启先读它续走。
5. 计划书生成后 Phase 6 校验:红线复查 + 负面检查,任一命中停修。
6. **计划书不是交付物,是开工单**——真正的产出是 Phase 8 当场验证过的东西,或 Phase 9 沉淀下来的资产。
