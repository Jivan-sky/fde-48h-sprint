# fde-48h-sprint

> 48h 需求 Sprint —— 把一份需求（文档 / 白皮书 / 会议纪要 / 口头一句话）在 48 小时内跑完一个冲刺：**辨真伪 → 提炼机会点 → 设计薄切片交付物 → 出计划书 → 当场验证**。

一个 Agent Skill（Claude Code / DSH）。计划书是 Sprint 的**起点**不是终点 —— 48 小时内要做出**能当场验证的东西**。

## 为什么做这个

FDE（前沿部署工程师）每天面对的是「客户说要一个 XX 系统」这类需求。多数时候：

- 需求是**伪需求** —— 拍板的人不是用的人
- 真需求埋在文档细节里，不在对方嘴上说的那句话
- 一上来就做「通用平台 / 管理系统」，做三个月没人用
- 经济账是老板拍脑袋的 N 万，不是算出来的

这个 skill 把上面这些坑固化成**铁律 + 对话阶段 + 固定骨架**，让 Agent 带着你走完一遍，而不是笼统地「帮你规划一下」。

## 六条铁律

1. **反平台是生死线** —— 整体系统替换 / 通用平台 / 管理系统 → 停，砍回单个薄切片
2. **价值在一线，不在拍板主管** —— 验证标准只有一句：真在一线干活的人当场说「这能帮到我」
3. **诚实条款** —— 没摸到的字段标「未摸到 / 待确认」，绝不编业务事实、绝不编数字
4. **经济账自己算** —— 不采信「老板拍板 N 万」，只认 `砍掉工时 × 人力单位成本 × 10-20%` 重算，算账过程给人看
5. **机会点必须带证据** —— 每个机会点标来源（文档哪段 / 哪句话 / 对话哪个回答），无证据标「待确认」
6. **失败也是产出** —— 判断是「伪需求」或经济账算不过 → 交付一页纸真伪结论，同样算交付

## 流程

| Phase | 做什么 | 产出 |
|---|---|---|
| 0 前置检查 | 输入是什么形态？有真数据源吗？有真在一线的人吗？ | — |
| 1 文档采矿 | 三张清单：表面需求 / 细节点 / 机会点候选（逐条带出处） | 采矿笔记 |
| 2 提问循环 | 每轮 ≤3 题，选择题带理由；辨真伪 | 真伪判断 + 证据链 |
| 3 收敛确认 | 一张要素表过目：需求真伪 / 机会点 / 交付形式 / 经济账 / 验证标准 | 用户确认 |
| 4 生成计划书 | 按固定骨架渲染，内容全部来自前三阶段 | 计划书 |
| 5 校验 | 红线复查 + 负面检查（有没有编数字 / 有没有偷偷做平台） | 通过或打回 |
| 6 下场 Sprint | 48h 本人零依赖端到端做出薄切片，当场找一线验证 | 能用的东西 |

## 交付形式

| 形式 | 何时选 |
|---|---|
| **F1** 48h 薄切片 | 有真实单据 + 有一线可当场验证（标准 FDE 交付） |
| **F2** 一页纸真伪结论 | 真伪是「伪」/ 经济账算不过（失败也是产出） |
| **F3** 现场工具 | 一线持续要用的动作，可脚本化（从 F1 升级） |
| **F4** 报告 / 复盘 | 对方只要结论不要工具（少做，别退化回咨询） |

## 设计要点

- **上下文预算表** —— 每个 Phase 只允许读指定文件，禁止一次性全读把上下文吃光（渐进式披露）
- **断点续走** —— 每阶段把关键信息写进 `planbook-state.md`，下次启动先读它，从断点继续
- **进度行约定** —— `【计划书 N/5 · 采矿】已读文档，表面需求 3 条，细节点 5 条，机会点候选 2 个——下一步：确认机会点`
- **骨架固定，内容不自由发挥** —— 计划书按固定骨架渲染，内容全部来自前三阶段已确认的信息

## 安装

放到 Agent 的 skill 目录即可（Claude Code / DSH 均扫描 `~/.claude/skills`）：

```bash
git clone https://github.com/Jivan-sky/fde-48h-sprint.git ~/.claude/skills/fde-48h-sprint
```

## 触发方式

给一份需求文档 / 白皮书 / 会议纪要，或直接说「帮我看这份需求文档」「把需求做成东西」「下场现场」。
