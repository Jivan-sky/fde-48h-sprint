# fde-48h-sprint

![fde-48h-sprint 封面](./assets/cover-1600x900.png)

> **FDE 现场作业 Sprint 与企业级 AI 落地手册（v4.6）**
>
> 接一份需求（文档 / 白皮书 / 会议纪要 / 口头一句话），跑完整条链路：
> **判客户层 → 建问题模型 → 辨真伪 → 勘测接口/数据/环境 → 复刻流程扫隐患 → 出计划书 → 48h 做 MVP → 深度开发 → 灰度 → 生产准入 → 持续迭代。**

一个 Agent Skill（Claude Code / Codex / DSH）。**48h 只证明 MVP，不证明生产可用；计划书是开工单，不是交付物。**

## 为什么做这个

FDE（前沿部署工程师）每天面对的是「客户说要一个 XX 系统」这类需求。多数时候：

- 需求是**伪需求**——拍板的人不是用的人；
- 真需求埋在文档细节里，不在对方嘴上说的那句话；
- 一上来就做「通用平台 / 管理系统」，做三个月没人用；
- 经济账是老板拍脑袋的 N 万，不是算出来的；
- **用错客户层的打法**——30 人小厂要省钱，200 人公司要进步，国央企要战略；
- 客户**之前已经试过同一个方案并失败了**，却没人问「为什么失败」；
- Demo 跑通就以为能上线，**忽略了权限、白名单、三权分离、审计、灰度、回滚**；
- 探索阶段「先点一下试试」，**误删了一张表，花两天恢复**。

这个 skill 把这些坑固化成**铁律 + 12 阶段 + 门禁 + 固定骨架**，让 Agent 带着你走完，而不是笼统地「帮你规划一下」。v4.6 把“动作分级、逐动作审计、写入门卡、sniffer 运行时 guard、回滚粒度、逐对象 before-image、Agent 执行书”做成可执行件。

**配套只读探查**：Phase 4 可调用 `web-capability-sniffer` 产出功能地图、接口轮廓、逐动作审计和可追溯/回滚预判；本 skill 按 `references/sniffer-handoff.md` 验收。报告是判断上下文，不是写许可。

## 三句话先记住

1. **48h 只证明 MVP，不证明生产可用。** MVP 是能力切片，生产是控制工程。
2. **探索阶段只理解系统，不改变系统。** 授权只扩大「可记录范围」，不扩大「可执行范围」。
3. **任何写入先有基线快照、逐对象 before-image、回滚对象和演练。** 只有整表快照、没有对象键映射和补偿数据，不叫可回滚；没有快照、没有回滚、没有审批的写入，叫赌博。

## 三种部署模式

| 模式 | 现场 | 能做什么 | 不能声称 |
|---|---|---|---|
| **D0 开放演示** | 自有设备/批准演示机；无客户生产数据 | 验证能力、交互、价值假设 | 企业可用、合规、可上线 |
| **D1 受控试点** | 客户内网/测试环境/沙盒；白名单、默认只读、脱敏/合成数据 | 验证切片、接口、权限、流程 | 生产可上线、全量可用 |
| **D2 生产** | 生产环境；变更审批、三权分离、灰度、审计 | 生产运行（需三重验收） | 无证据的「应该没问题」 |

## 交付路线：MVP → 深度开发 → 灰度 → 生产 → 迭代

| 阶段 | 目标 | 环境 | 退出条件 |
|---|---|---|---|
| **M0 MVP** | 证明一个薄切片对一线有价值 | D0/D1 | 一线原话验证，或转 F2；不做客户生产写入 |
| **M1 深度开发** | 把 MVP 做成可交付工程 | D1 | UAT 就绪 + 控制初验 |
| **M2 灰度** | 小范围真实暴露 | D1→D2 | 指标达标 + 无 P0/P1 + 回滚可用 |
| **M3 生产** | 正式交付并可持续运行 | D2 | 三重验收 + G6b |
| **M4 迭代** | 版本化演进、控制漂移 | D2 + 变更 | 下一版验收或退役 |

## 16 条铁律

1. 反平台是生死线
2. 价值在一线，不在拍板人
3. 分层决定打法
4. 诚实条款 + 证据分级
5. 经济账自己算，价值不等于裁员
6. 问题定义权归自己
7. 弱意愿不投入
8. 边界与承诺纪律
9. 本人零依赖端到端；失败也是产出
10. 模式先行（D0/D1/D2）
11. **探索只读**（写操作执行数 = 0）
12. 控制面不可绕过；三权分离
13. 约束下沉 + 制品定性
14. 选择权在人；控制红线不可谈判
15. **写前快照；写后校验；可回滚**
16. 三重验收 + 证据可追溯

## 门禁（G1-G6）

| 门 | 位置 | 必须确认 |
|---|---|---|
| **G1** | Phase 0 末 | 路线 + 模式 + 种子约束 + 能力清单 + 控制角色 |
| **G2** | Phase 3 末 | 真伪结论 + 证据链 + 客户层/一号位 |
| **G3** | Phase 4 末 | 接口三档 + 环境可达 + 数据分级/跨境 + 模型可用 + 可追溯/回滚 + 卡点预案 |
| **G4** | Phase 6 末 | 三区表签字（业务 + 控制） |
| **G5** | Phase 7 末 | 计划书过目 + 控制角色过目 |
| **G6a** | Phase 10 下场前 | 下场授权（现场/脚本/真实单据） |
| **G6b** | D2 前 | 生产准入（变更/UAT + AI 评测/灰度/回滚/审计/运行 owner） |

**G6 是一个门号，内部分「下场段」和「生产段」两段，不新增 G7。**

## 探索只读与写前快照

- 探索阶段：写操作执行数必须为 **0**；授权只扩大可记录范围，不扩大可执行范围；不重放请求、不做主动扫描/越权探测、不导出 HAR。见 `references/exploration-safety.md`。
- 写入之前：基线快照（与写入故障域隔离）、逐对象 before-image/对象键映射、影响范围、回滚对象、回滚演练、dry-run、审批、幂等/限额/已演练的 kill switch；台账不可用即停。写入之后：read-back + 写后快照 + 证据台账。见 `references/write-safety.md`。
- 每次写客户系统前填 `references/write-gate-record.md`；测试环境、共享环境、灰度和生产都适用。M0 不写客户系统，必须写时改只读/一次性沙盒/人工桥。
- 回滚本身也是受控写操作：审批、台账、read-back、回滚后哈希核对，不能由 Agent 临场自创。
- 数据库场景要求：事务/备份、行数 + 关键字段哈希、可恢复路径、恢复验证、禁止无 `WHERE` 的更新/删除、探索阶段禁止 DDL。

## 交付形式与停止条件

| 形式 | 何时选 |
|---|---|
| **F1** 48h 薄切片（M0） | 有真实单据 + 有一线可当场验证 |
| **F2** 一页纸真伪结论 | 真伪是「伪」/ 经济账算不过 |
| **F3** 现场工具 | 从 F1 升级，一线持续用 |
| **F4** 报告/复盘 | 对方只要结论不要工具 |
| **F5** 可复用制品 | 流程固化、多场景复用；D2 还需运行/回滚/证据件 |

停止条件三类都要写：**范围停 / 时间停 / 价值停**，且必须让对方认可。

## 安装

```bash
git clone https://github.com/Jivan-sky/fde-48h-sprint.git ~/.claude/skills/fde-48h-sprint
```

```powershell
git clone https://github.com/Jivan-sky/fde-48h-sprint.git $HOME\.claude\skills\fde-48h-sprint
```
