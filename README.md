# fde-48h-sprint

> **FDE 现场作业 Sprint(v3)** —— 把一份需求(文档 / 白皮书 / 会议纪要 / 口头一句话)跑成一个冲刺:
> **判客户层 → 建问题模型 → 辨真伪 → 提炼机会点 → 设计薄切片 → 出计划书 → 过一号位沟通与 POC → 48h 本人端到端下场验证 → 沉淀与换单。**

一个 Agent Skill(Claude Code / DSH)。**计划书是 Sprint 的开工单,不是交付物**——真正的产出是 48h 内当场验证过的东西,或下一次换单。

## 为什么做这个

FDE(前沿部署工程师)每天面对的是「客户说要一个 XX 系统」这类需求。多数时候:

- 需求是**伪需求** —— 拍板的人不是用的人
- 真需求埋在文档细节里,不在对方嘴上说的那句话
- 一上来就做「通用平台 / 管理系统」,做三个月没人用
- 经济账是老板拍脑袋的 N 万,不是算出来的
- **用错客户层的打法** —— 30 人小厂要省钱,200 人公司要进步,国央企要战略,一套打法通吃的单子必死
- 客户**之前已经试过同一个方案并失败了**,却没人问「为什么失败」

这个 skill 把上面这些坑固化成**铁律 + 十阶段 + 固定骨架**,让 Agent 带着你走完一遍,而不是笼统地「帮你规划一下」。

## 九条铁律

1. **反平台是生死线** —— 整体系统替换 / 通用平台 / 管理系统 / 中台 / 低代码底座 → 停,砍回单个薄切片;也不把早就在线填表 / 发链接 / OCR 当杀手锏。
2. **价值在一线,不在拍板人** —— 验证标准只有一句:真在一线干活的人当场说「这能帮到我」。
3. **分层决定打法** —— 30 人降本增效型(要省钱)/ 约 200 人进步型(要进步)/ 国央企战略型(要战略 + 安全合规)。先判层,再决定商务 / 产品 / 研发怎么打。
4. **诚实条款 + 证据分级** —— 证据分 L1 已闭合 / L2 现场素材 / L3 公开口播;没摸到的标「未摸到 / 待确认」,绝不编业务事实、绝不编数字。
5. **经济账自己算,价值不等于裁员** —— 只认 `砍掉工时 × 人力单位成本 × 10-20%` 重算,并把过程给人看;不替老板制定裁员计划。
6. **问题定义权归自己** —— 客户说的往往是症状,必须自己产出**问题模型**;每个机会点标来源,无证据不进计划书正文。
7. **弱意愿不投入** —— 「有意思 / 回头聊 / 发点资料看看」都是弱信号;弱信号下不发长问卷、不免费出完整方案、不启动重 POC。
8. **边界与承诺纪律** —— 先说不做什么(只读 / 不外发 / 可审计);不承诺「包在我身上 / 一周上线 / 100% 准」。
9. **本人零依赖端到端;失败也是产出** —— 输入自己拿、脚本自己写、验证自己做,不外包不等人;判断是伪需求或账算不过,交一页纸 F2 结论,同样算交付。

## 两条路(FDE 与 ANC 概念分开,入口统一)

Phase 0 先选一条,再开工:

| 路线 | 讲什么 | 进入时读 | 沉淀落点 |
|---|---|---|---|
| **A · FDE 交付(默认)** | 人怎么干活:判层 → 采矿 → 问题模型 → 计划书 → 下场验证 | 不读 ANC 相关 | 知识库 / 脚本 / Skill |
| **B · ANC 架构** | 活儿沉淀在哪:在 A 的基础上,把这一刀接回 ANC 树干 | `references/anc-context.md` | 树干七连接件(Context / 权限 / Skill / 反馈) |

两条路共用 Phase 2-5、7-8 的 FDE 内核;差异只在四处:**进入时读什么、Phase 1 用什么词汇、Phase 6 多查什么、Phase 9 落到哪**。选 A 就不读 ANC,选 B 才读,不要混着用。
## 流程(0-9)

| Phase | 做什么 | 产出 |
|---|---|---|
| 0 前置检查 | 输入什么形态?有真数据源 / 真在一线的人 / 一号位吗? | — |
| 1 客户分层(九宫格) | 判客户在哪一层 + 当前联系人是不是一号位 | 客户层 = X;一号位 = 谁 |
| 2 文档采矿 + 问题模型 | 六类线索挖机会点;五要素建问题模型(带假设 / 已验证 / 已推翻) | 采矿笔记 + 问题模型 v1 |
| 3 提问循环(Echo 甄别) | 每轮 ≤3 题选择题;辨真伪;销售 / BD 必答 E 组 | 真伪判断 + 证据链 |
| 4 收敛确认 | 一张要素表过目(含客户层 / 一号位 / 停止条件) | 用户确认 |
| 5 生成计划书 | 按 v3 十节固定骨架渲染 | 计划书 |
| 6 校验 | 红线复查 + 负面检查 | 通过或打回 |
| 7 一号位沟通 & POC 一页纸 | 机会卡 / 30 秒表达 / 判强弱意愿 / POC 一页纸 | POC 一页纸 |
| 8 下场 Sprint(48h) | 本人零依赖端到端做出薄切片,当场找一线验证 | 能用的东西 |
| 9 沉淀与换单 | 写回问题模型 / 踩坑 / 脚本 / Skill;定换单口径 | 沉淀资产 + 下一单 |

## 交付形式与停止条件

| 形式 | 何时选 |
|---|---|
| **F1** 48h 薄切片 | 有真实单据 + 有一线可当场验证(标准 FDE 交付) |
| **F2** 一页纸真伪结论 | 真伪是「伪」/ 经济账算不过 / 之前有人做过但说不清为什么失败 |
| **F3** 现场工具 | 一线持续要用的动作,可脚本化(从 F1 升级) |
| **F4** 报告 / 复盘 | 对方只要结论不要工具(少做,别退化回咨询) |

**停止条件(承诺前写死,必须让对方也认可)**:范围停(长到哪就砍)/ 时间停(到点就交付)/ 价值停(账算不过就停)。详见 `references/delivery-forms.md`。

## 设计要点

- **上下文预算表** —— 每个 Phase 只允许读指定文件,禁止一次性全读把上下文吃光(渐进式披露)。
- **断点续走** —— 每阶段把关键信息写进 `planbook-state.md`,下次启动先读它,从断点继续。
- **进度行约定** —— `【FDE Sprint N/9 · 采矿】已读文档,表面需求 3 条,细节点 6 条,问题模型 v1,机会点候选 2 个——下一步:确认机会点`。
- **骨架固定,内容不自由发挥** —— 计划书按十节骨架渲染,内容全部来自前四阶段已确认的信息。
- **纯 Markdown,零运行时** —— 不放脚本、不引入任何依赖;skill 的读者是 Agent,交付物是判断与文档。
- **FDE 与 ANC 分开** —— 默认路线 A(FDE 交付)不碰 ANC;只有选路线 B 时,才把这一刀接回 ANC 树干。见 `references/anc-context.md`。

## 安装

放到 Agent 的 skill 目录即可(Claude Code / DSH 均扫描 `~/.claude/skills`):

```bash
git clone https://github.com/Jivan-sky/fde-48h-sprint.git ~/.claude/skills/fde-48h-sprint
```

## 触发方式

给一份需求文档 / 白皮书 / 会议纪要,或直接说「帮我看这份需求文档」「把需求做成东西」「下场现场」「客户分层」「问题模型」。
